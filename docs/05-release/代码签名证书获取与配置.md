# 代码签名证书：获取与配置（D6 补完文档）

- 状态：待用户决定何时启用（1.0.0 暂按"无签名"发布，本文件只在需要时照做）
- 关联：`apps/desktop/electron-builder.yml`（已留注释开关）、`docs/05-release/2026-11-12-首次安装指引.md`
- 结论先行：**无需改任何代码**，证书到位后只改环境变量 + 取消 yml 两行注释即可签署 Windows 安装包；macOS 另需 Apple Developer ID 与公证。

---

## 1. 为什么需要签名

| 平台 | 不签名的后果 | 签名后的效果 |
|---|---|---|
| Windows | SmartScreen 弹"未知发布者"/"可能有害"，用户需多点几次才能装 | 有发布者身份，SmartScreen 信誉随时间累积；EV 证书可即时建立信誉 |
| macOS | Gatekeeper 拦截，需"右键→打开"或关 SIP 级信任 | Developer ID 签名 + 公证后正常安装 |
| Linux | deb/rpm/AppImage 一般不强制签名 | 内部分发通常不需要 |

> 1.0.0 当前选择"无签名"，属预期行为（见首次安装指引）。本文件是"哪天想加了怎么加"的操作手册。

## 2. Windows 代码签名证书

### 2.1 证书类型（先定档，再买）

| 类型 | 验证强度 | 智能屏信誉 | 形态 | 价格量级（年） | 采购周期 |
|---|---|---|---|---|---|
| OV（组织验证） | 验证企业真实存在 | 需累积（装量上来后几周到数月） | `.pfx` 文件 + 密码，可纯软 | 约 ¥1k–3k | 1–3 天 |
| EV（扩展验证） | 严格审核 + 法律文件 | **即时**消除 SmartScreen 警告 | 必须硬件令牌（USB/SafeNet/云 HSM） | 约 ¥3k–6k+ | 1–3 周（含令牌邮寄） |

- 内部/小范围分发：先上 **OV** 即可，性价比高。
- 面向外部大量分发、受不了 SmartScreen 红框：**EV**。

### 2.2 去哪买（常见 CA，自行比价）

- DigiCert（贵、稳、信誉好）
- Sectigo / Comodo（性价比高，常见选择）
- GlobalSign
- Certum（欧盟，价格友好，OV 常用）
- 国内代理：多家 SSL 服务商可代开上述品牌代码签名证书

> 认准"Code Signing"证书，不是 SSL 证书。代码签名证书专用于给 `.exe`/`.msi`/`.dll` 签名。

### 2.3 拿到后是什么形态

- 标准交付物：**PKCS#12 `.pfx` 文件**（内含证书 + 私钥）+ 导出时设的**密码**。
- 也可选择把证书装进 Windows 证书存储（个人/My 存储），electron-builder 用 `CSC_NAME`（证书主题）引用；但**文件形态（.pfx + 密码）最通用、最易于 CI/本机复用**，本文件按文件形态讲。

### 2.4 配置（零代码改动）

1. 打开 `apps/desktop/electron-builder.yml`，取消第 31–33 行注释：
   ```yaml
   win:
     # …其他配置…
     certificateFile: ${env.WIN_CSC_FILE}        # 指向你的 .pfx 绝对路径
     certificatePassword: ${env.WIN_CSC_KEY_PASSWORD}   # .pfx 密码
   ```
2. 在当前 shell / CI Secrets 设置两个环境变量（**不要写进仓库、不要提交**）：
   ```bash
   # Windows（本机临时）
   set WIN_CSC_FILE=C:\secrets\sshk-tools-code-sign.pfx
   set WIN_CSC_KEY_PASSWORD=你的pfx密码
   # 或 PowerShell
   $env:WIN_CSC_FILE="C:\secrets\sshk-tools-code-sign.pfx"
   $env:WIN_CSC_KEY_PASSWORD="你的pfx密码"
   ```
3. 正常构建：`pnpm dist`（或 `pnpm release`）。electron-builder 自动读取这两个变量对 NSIS/portable 安装包签名。

### 2.5 安全红线（务必遵守）

- `.pfx` 文件与密码**绝不进 git**；`.gitignore` 已忽略 `dist/`，但证书建议放在仓库之外的专用目录（如 `C:\secrets\` 或 CI Secret）。
- 本机环境变量用临时会话设置，不要写进 `.bashrc`/`.zshrc`/系统环境变量长期留存。
- CI：只在仓库 Secrets / 环境里配置，构建日志中**不要 echo 密码**。
- 私钥泄露即作废，立刻联系 CA 吊销重签。

## 3. macOS 签名 + 公证（如未来要发 Mac 版）

macOS 额外要求：**Developer ID 证书** + **公证（Notarization）**。

### 3.1 前置

- 加入 **Apple Developer Program**（约 $99/年）。
- 在 developer.apple.com 申请 **Developer ID Application** 证书，下载安装到钥匙串。
- 准备一个 **App 专用密码** 或 **API Key（推荐）** 用于公证。

### 3.2 配置

1. `electron-builder.yml` 的 `mac` 段：
   ```yaml
   mac:
     hardenedRuntime: true     # 取消原 false
     # 公证在 afterSign 钩子或 mac.notarize 配置；官方推荐用 env 注入凭据
   ```
2. 设置环境变量（CI Secrets / 临时 shell）：
   ```bash
   APPLE_ID=你的AppleID@xxx.com
   APPLE_APP_SPECIFIC_PASSWORD= app专用密码
   APPLE_TEAM_ID=你的10位团队ID
   # 或（推荐，避免密码泄露）：
   APPLE_API_KEY=AuthKey_XXXX.p8 路径
   APPLE_API_KEY_ID=XXXX
   APPLE_API_ISSUER=issuer-uuid
   ```
3. 构建时 electron-builder 自动签名 + 调用 `notarytool` 公证并 staple。

> macOS 不支持"永久最高权限"打包（见 yml 注释的硬限制），签名/公证只解决"未知开发者"拦截，不解决提权。

## 4. Linux（可选）

- deb/rpm/AppImage 一般不强制签名。如需，可对 deb 做 GPG 签名（`dpkg-sig`），属进阶项，内部分发通常跳过。

---

## 5. 启用签名前的检查清单（照着打勾）

- [ ] 已购买并拿到 `.pfx`（Windows）/ Developer ID（Mac）
- [ ] `.pfx` 与密码已放到仓库外安全位置，**未提交 git**
- [ ] 已设置 `WIN_CSC_FILE` / `WIN_CSC_KEY_PASSWORD`（Windows）或 Apple 系列变量（Mac）
- [ ] 已取消 `electron-builder.yml` 对应注释，并设 `mac.hardenedRuntime: true`（Mac）
- [ ] 本地跑一次 `pnpm dist`，确认安装包已带签名（Windows：`Get-AuthenticodeSignature 安装包路径`；Mac：`codesign -dv --verbose=4` + `spctl`）
- [ ] 在干净虚拟机/实机验证 SmartScreen / Gatekeeper 不再红框拦截（至少 OV 需观察信誉累积）

---

## 6. 一句话总结

**代码不动，证书到位后只做两件事**：① 取消 `electron-builder.yml` 里 `win.certificateFile` / `win.certificatePassword` 的注释（Mac 再把 `mac.hardenedRuntime` 改为 `true`）；② 在环境/CI 里填 `WIN_CSC_FILE`、`WIN_CSC_KEY_PASSWORD`（及 Apple 系列变量）。然后正常 `pnpm dist` 即产出带签名安装包。
