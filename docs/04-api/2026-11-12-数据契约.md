## 1. 术语、ID 与时间规范

| 项 | 约定 |
|---|---|
| 应用 / 工具 | 应用 = 整个安装客户端；工具 = `tools/` 下的工具包 |
| ID | `<前缀>_<ulid>`：`brd_ / tpl_ / tplv_ / frg_ / frgv_ / mail_ / pst_ / prv_` |
| **时间** | **一律北京时间 Asia/Shanghai（UTC+8），无特殊情况不得使用 UTC** |
| 存储格式 | ISO 8601 **带 `+08:00` 偏移**：`2026-11-12T21:08:28+08:00` |
| 统一工具 | `packages/shared/time.ts`（dayjs + timezone 插件）：`now() / format() / parse() / toFileName()` |
| **禁令** | 禁止 `new Date().toISOString()`（输出 UTC）；禁止裸 `Date.now()` 直接入库；ESLint 规则拦截 |
| 覆盖范围 | `createdAt` / `updatedAt` / `lastGeneratedAt` / `exportedAt` / changelog 日期 / zip 文件名 / 迁移记录 / token 有效期 / 日志时间戳 / 列表展示 |
| 外部数据 | 邮件平台导出 csv 若带 UTC 时间 → **入口处转北京时间再入库** |
| 系统值 | `fs.stat` 的 mtime/ctime 是 epoch，展示层统一转北京时间 |
| 版本不可变 | `TemplateVersion` / `FragmentVersion` 内容不许原地改，改 = 新版本（D8） |
| 软删除 | 被引用实体删除改为归档 `archived:true`，硬删仅在无引用且二次确认后 |
| **产物路径** | 一律相对 `app.outputDir`，**禁止存绝对路径**；导入到别的机器时重映射 |

## 2. 领域模型：品牌树（需求 13）

```
Brand
├── Template ── TemplateVersion   [slots / dataSchema / sampleData / 不可变]
```

### 2.2 片段候选查询（两道过滤下推到 Repository）

```
listCandidateFragments(templateVersionId, slotType)
  → NeDB query:
      brandId  = 模板版本.brandId
      type     = slotType
      _id 不在 任一 fragmentVersion.policy.blacklist（含按族展开的 ID）
      whitelist 为空 或 包含 templateVersionId
      archived = false
  → 按 version 倒序返回候选
```

**黑名单优先**：命中黑名单 → 禁用；否则白名单为空 → 全可用；否则白名单含 → 可用，不含 → 禁用。

### 2.3 D14「ID 怎么知道」→ 名单的配置数据结构

名单**存 ID，但 UI 不暴露 ID**（选型稿 §4.2.1）：

| 机制 | 数据侧 |
|---|---|
| 三级选择器 | 前端按 `Brand → Template → TemplateVersion` 查出名称展示，选中后写入 `tplv_…` 到 `policy` |
| 按族批量 | 允许存 `tpl_…`，查询层展开为该族所有版本 ID；也可在保存时直接展开为版本 ID 列表 |
| 双向反查 | `repository.findPoliciesByTemplateVersion(tplv_…)` / `findPoliciesByFragmentVersion(frgv_…)` |
| 悬空清理 | 删除/归档模板版本时扫描所有 `policy.blacklist/whitelist`，移除失效 ID 并记录数量 |
| 预览验证 | 直接调 §2.2 的候选查询，配置页「试一试」实时出结果 |

### 2.4 「复制保存」的两种分支（需求 9 / D8）

| 用户选择 | 写入动作 |
|---|---|
| 存为**新版本** | 新建 `TemplateVersion`，`templateId` 不变、`version=latest+1`，复制 `slots/dataSchema/sampleData` |
| 存为**另一种模板** | 新建 `Template` + `TemplateVersion(v1)`；**brandId 可改（跨品牌）**；`origin=custom`；与源族无关 |

系统模板（`origin:system`）只能走第二种，副本强制 `custom`。片段同理。

### 3.1 读写规则

| 规则 | 说明 |
|---|---|
| 统一入口 | `ConfigService.get/set(namespace, key, value)`；工具只读写 `tools.<id>.*` |
| 默认值 | 每工具 `defaultConfig`；导入旧包缺字段逐级补默认 |
| 广播 | 主进程写成功 → IPC `config:changed { namespace, key }` → 响应式刷新 |
| 脱敏 | 界面读 `app.llm.providers` 时 apiKey 显示 `••••`；导出时剔除 |
| 校验 | 每工具配置有 JSON Schema，写前校验，非法值拒绝并保留旧值 |
| 时间 | 配置内时间字段（如 token 有效期基准）一律北京时间 |

### 3.3 环境变量（D18，只读检测，不写入配置）

| 变量 | 值 | 作用 |
|---|---|---|
| `SSHK_TOOLS_ALLOW_SECRET_MIGRATION` | 未设置 / 其他（默认） | 密钥不进包，导入后引导重填 |
| `SSHK_TOOLS_ALLOW_SECRET_MIGRATION` | `1` / `true` | 导出时可加密携带密钥；导入时显示「还原密钥」入口 |

> 该变量**只是功能开关**，不参与加密、不落盘、不进日志；两端都要开启。真正的安全边界是迁移口令（§4.3）。

## 4. 导入导出包格式（需求 6）

```jsonc
// manifest.json
{
  "schemaVersion": 1,
  "appVersion": "0.1.0",
  "exportedAt": "2026-11-12T21:08:28+08:00",   // ★ 北京时间
  "sourceOS": "win32",
  "includes": ["settings", "data", "assets", "outputs"],
  "counts": { "brands": 2, "templates": 5, "templateVersions": 9,
              "fragments": 7, "fragmentVersions": 12, "mails": 23, "posters": 7 },
  "secrets": "excluded",          // excluded | encrypted（D18）
  "secretKdf": null,              // 加密时填 { algo, iterations, salt, nonce }（不含口令/密钥）
  "checksum": "sha256:<对整个包内容计算>"
}
```

```
backup.zip
├── manifest.json
├── settings/{ app.json, tools.json }
├── data/{ brands, templates, templateVersions, fragments, fragmentVersions,
│          mails, posters, datasources }.json
├── assets/                 # 模板本地 css/图片、品牌 logo、上传的原始数据源
├── outputs/                # 覆盖式单份产物（导出开关，默认开）
├── secrets.enc             # 仅 secrets:"encrypted" 时存在（AES-256-GCM 密文）
└── README.txt              # 还原说明 + 「需手动补：右键菜单重新注册」
```

### 4.1 导出范围

| 进包 | 不进包 |
|---|---|
| 应用配置、工具配置、provider 列表（无密钥） | 模型 apiKey（默认；开关开启时走 §4.3 加密） |
| 品牌/模板/片段（族+版本+样例数据）、邮件+海报记录 | 系统模板本体（安装包自带，只导出引用关系） |
| 产物 HTML/PNG（默认开） | 缓存/日志/`.tmp`/NeDB 索引 |
| — | **机器绝对路径**（包内全相对路径，导入重映射到目标机 `outputDir`） |

### 4.2 导入流程与失败回滚

```
① 校验 zip：路径穿越 / 条目数 / 单文件与总大小上限 / checksum
② 读 manifest：schemaVersion 比对 → 旧包 migrations；包比应用新 → 拒绝并提示升级
③ 快照当前数据 → .tmp/import/pre-import-backup.zip
④ 解压到 .tmp/import/staging/ → 重映射相对路径到本机 app.outputDir → 补默认配置
⑤ 原子替换（停 NeDB、写队列排空、compact）
⑥ 重建索引 / 重新注册机器级项（右键菜单、开机自启）
⑦ 若 secrets:"encrypted" 且本机开关开启：按 §4.3 解密还原密钥
⑧ 失败 → 回滚到 ③ 的快照，保留现场日志
⑨ 完成页：提示重填/已还原 N 个密钥 + 「立即重新注册右键菜单」
```

| 策略 | 默认 | 说明 |
|---|---|---|
| 冲突 | **整包覆盖**（D17） | 高级选项可按 ID 合并（取 `updatedAt` 较新，注意该字段是北京时间带偏移字符串，字典序可比较） |
| 幂等 / 可取消 | 是 | 同包重复导入结果一致；取消后保持原状 |

### 4.3 加密密钥迁移契约（D18）

```
导出（env 开关 = 1）
  ① 二次确认 + 提示「将导出模型密钥，请妥善保管 zip」
  ② 用户输入迁移口令（不写环境变量、不落盘、不进日志）
  ③ PBKDF2/Argon2id(口令, 随机 salt, iterations) → key → AES-256-GCM 加密 secrets
  ④ secrets.enc 落包；manifest.secrets="encrypted"；secretKdf={algo,iterations,salt,nonce}
导入（env 开关 = 1）
  ⑤ 输入同一口令 → 派生 key → 解密 → 用本机 safeStorage 重新加密落盘
  ⑥ 口令错误/缺失 → 跳过密钥，其余数据照常还原并明确提示
```

| 字段 | 说明 |
|---|---|
| `secrets.enc` | 密文；不得含任何明文口令、派生密钥、原始 apiKey 文本 |
| `manifest.secretKdf` | 只放 KDF 参数与 salt/nonce，**绝不放口令或密钥** |
| 日志 | 只记「已导出加密密钥 / 已还原 N 个密钥」，不记口令与密钥内容 |
| 禁止 | 明文密钥进包；把口令放环境变量（会进 shell history / 进程列表 / CI 日志） |

### 4.4 产物目录与导入的联动

- 包内 `outputs/*` 与 `assets/*` 路径全部**相对**；导入时按目标机 `app.outputDir` 解析。
- `settings/app.json` 里 `outputDir` **不导入**（这是机器相关的本地设置）；若包内有该字段，导入时忽略并提示「已保留本机产物目录」。
- 若目标机 `outputDir` 不存在 → 按 §8 的预检规则创建或让用户选择。

## 8. 产物目录迁移契约（第三轮需求 5 / D21）

```jsonc
// <outputDir>/.storage-manifest.json
{
  "schemaVersion": 1,
  "dirType": "sshk-outputs",
  "createdAt": "2026-11-12T21:08:28+08:00",   // 北京时间
  "migratedFrom": null,                         // 上一次旧目录（脱敏展示）
  "migratedAt": null,
  "files": [ { "rel": "outputs/edm/mail_…/final.html", "size": 12345, "sha256": "…" } ],
  "pendingCleanup": [ ]                        // 待清理的旧目录文件清单
}
```

| 步 | 契约 |
|---|---|
| ① 预检 | `validateDir(newDir)` 返回 `{ writable, freeBytes, requiredBytes, isSubdirOfOld, isSystemDir, isNetworkDrive, warnings[] }`；任一硬条件不满足即拒绝 |
| ② 停写 | `repository.pauseWrites()` + 等待在途生成任务；超时中止且不破坏任务 |
| ③ 复制 | 复制到 `<newDir>/.migrating/`，逐文件写 `{rel,size,sha256}` 清单；**不直接覆盖现有同名文件** |
| ④ 校验 | 文件数 / 总字节 / 抽样 hash / 产物可打开 / manifest 可解析；不一致即清理临时目录并回退 |
| ⑤ 原子切换 | 单事务写 `app.outputDir` + 重设 repository/shares 的根解析；`config:changed` 广播；重开写队列 |
| ⑥ 清理 | 见下方红线；结果写入 `pendingCleanup` 与迁移历史 |

**清理旧目录红线**

| 规则 | 说明 |
|---|---|
| 只删已登记文件 | 严格按迁移清单里的 `rel` 逐项删除；**绝不递归删除用户目录本身**（用户可能设在桌面/文档/下载/共享盘根） |
| 不做 `rm -rf` | 逐文件删、逐项记录；只移除应用自有的空 `outputs/`、`assets/` 目录 |
| 二次确认 | 弹窗列出将删除的路径、文件数、占用空间；可勾选「暂不删除」 |
| 延迟删除 | 默认标记「待清理」，下次启动复核新目录完好后再删；可立即删 |
| 失败不回滚 | 删除失败/占用/权限不足只记录，不阻断已成功的迁移 |
| 追溯 | 迁移前把旧目录清单 + checksum 存一份到新目录 |

**界面**：应用配置 → 存储：当前目录 / 占用空间 / 文件数 / 「更改…」/ 迁移进度 / 校验结果 / 迁移历史 / 待清理清单。StatusBar 常显当前产物目录。

**默认迁移范围（待 D21 确认）**：`outputs/` + `assets/`；`settings` / `secrets.bin` / NeDB `db/` 保留在 `userData`。若确认连 `db/` 一起搬，只需在清单里增加该项，流程不变。

## 补记（2026-11-13）：EDM 目录骨架与 css 协调

### A. 目录树（运行时由 `ensureOutputDirs()` 幂等创建，品牌层级由写入方按需建）

```
<outputRoot>/
  assets/
    templates/<brandCode>/        # 品牌模板源：njk + 该品牌独立 css（随版本落盘）
      procell/promo-v2.njk
      procell/promo-v2.css
    edm/css/                      # EDM 公共 css（跨品牌共享）
      base-reset.css              # 样式重置（normalize + 邮件适配，不手写）
      uno.css                     # unocss 原子类产物（渲染时按需生成）
  outputs/edm/<mailId>/…          # 三阶段产物（assembled / inlined / final，不变）
```

### B. css 三态协调（沿用既有 `source.cssMode: inline | local | external`）

| 模式 | 存放 | 渲染行为 |
|---|---|---|
| inline | 内容在 DB（templateVersions / fragmentVersions） | 直接进 `<style>` |
| local | `assets/templates/<brandCode>/*.css` | `resolveSafe` 读文件 → 进 `<style>`（邮件不能引本地文件，最终由 juice 内联） |
| external | 线上 URL | 保留 `<link>`，渲染时给出邮件兼容性警告 |

汇集顺序（assembled 阶段统一注入 head）：`base-reset.css` → `uno.css` → 品牌/模板 css → 模板内联 style → juice 内联下沉到 style 属性。

### C. normalize.css + unocss（结论：可行，已排期实现）

- 管线已有 juice 内联，原子 class 会被内联成 style 属性，Gmail / 企业微信等支持 style 属性，链路兼容。
- Outlook 桌面版（Word 引擎）不支持 flex/grid：布局原子类需保守（表布局），由模板规范约束，unocss 本身无碍。
- unocss 需**独立于桌面应用**单独配置（content 指向 EDM 模板/片段源文件），并关闭其默认 preflight，重置统一用 base-reset.css，避免双 reset 冲突。
- 实现：edm 渲染管线在 assembled 前插「css 汇集」步骤 + unocss 生成步骤；normalize.css 作为 base-reset.css 的底稿引入。
