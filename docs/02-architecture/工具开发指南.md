# 工具开发指南（从零建一个工具）

> 目标读者：需要在**脱离 AI 协助**的环境下手工创建工具的开发者。
> 活模板：`tools/template-tool/`（全能力示例，含形态 2 二级配置页示范）；任何拿不准的写法直接抄它。
> 快捷路径：dev 模式下「更多 → 创建工具（开发者）」或「应用管理 → 应用设置 → 工具与权限 → 创建工具」，向导生成全部骨架后只需填业务逻辑（见 §一）。
>
> **边界前提（D53 · 2026-11-21 定稿）**：P4-8 起文件管理 / 模型管理 / 分享管理三个基础能力模块已是**应用本体**（`apps/desktop/src/renderer/pages/app-admin/{files,models,share}`），不再接受任何新的「基础能力工具」。**新工具只能做纯工具**（业务自包含、可禁用、可分发），经 `createSafeHost` 单向消费应用能力（见 §四.3）。

## 一、两条创建路径

| 路径 | 适用 | 步骤概要 |
|---|---|---|
| **向导（推荐）** | dev 环境快速起步 | 分步表单填基本信息 / 菜单页面 / 能力权限 / 配置分组 → 右侧实时 JSON 预览 → 确认创建 → **重启 `pnpm dev` 生效** |
| **手动** | 无 dev 环境或想彻底理解结构 | 按 §二 建目录 → 按 §三 手写 manifest → 按 §四 写入口 → 跑 §六 门禁 |

两条路径产物完全同构；向导生成的每个文件都可以当手动参考。

## 二、目录结构（内建 / 外部同构 · T1 目标规范）

```
tools/<id>/                        # 目录名必须 === manifest.id（kebab-case，见 §2.1）
├── tool.manifest.json             # 唯一事实源：元数据、菜单、权限、配置项全在这
├── package.json                   # name: @sshk/<id>；exports 暴露 ./main（如有）与 ./renderer
├── tsconfig.json                  # extends ../../tsconfig.base.json
├── assets/icon.svg                # icon:"auto" 必备文件（CR-10 教训）；48x48 或 64x64
├── src/
│   ├── index.ts                   # 渲染入口（re-export 渲染壳）
│   ├── main/                      # 仅"有主进程能力"的工具才有（纯渲染形态省略，见 §2.2）
│   │   ├── index.ts               # 主进程入口：默认导出 (ipcMain, deps) => void（D41 强契约）
│   │   └── ipc.ts                 # 通道注册；复杂可再拆 ipc/ 目录按域分文件
│   └── renderer/
│       ├── <PascalId>Page.vue     # 渲染层壳：menu 分发 + ToolPageLayout（宿主只发现这一个文件）
│       ├── host.ts                # 宿主能力声明：createSafeHost 通道映射（H2 零裸调）
│       ├── store.ts               # 响应式状态：toolId 注入 + 通道调用封装（禁 shared.ts 命名）
│       ├── pages/                 # 只放页面 XxxPage.vue（禁放弹框/组件/纯逻辑）
│       ├── components/            # 组件 + 弹框（弹框也是组件）
│       └── composables/           # use*.ts 组合式
└── scripts/                       # 工具自有脚本（可选）
```

分层铁律（`check-boundaries.mjs` 强制）：renderer 禁引 `electron`/`node:fs`/`BrowserWindow`；main 禁引 `.vue`/`element-plus`/`window.api`；工具之间禁止互相 import。

### 2.1 工具 id 命名规则（B27）

- **kebab-case、小写字母开头、仅小写/数字/连字符、2-64 位，且必须与目录名一致**（创建后不可改，toolId 记账/鉴权/配置键都依赖）。
- **后缀不统一合法**：`edm-studio` / `badge-studio` / `template-tool` 各自语义贴切即可，不强求统一后缀（如一律 `-manager`）；命名合法即可。
- **存量 id 不改**（`file-manager` / `model-manager` / `share-manager` 已随 P4-8 退役为**应用模块 id**，仅作配置键命名空间与分享归属校验保留，不再是工具 id）。

### 2.2 纯渲染形态（无 main 的工具）

- 不需要主进程能力的工具**可以不建 `src/main/`**：manifest `plugin` 省略 `main` 字段（只声明 `renderer`），渲染层只消费宿主能力（`window.api` 已放行的宿主通道 + `config:get/set`）。
- 原 model-console / file-manager / share-manager 即纯渲染形态（P4-8b 已并入应用本体）；现役纯工具中如后续去掉 main 也属此形态。
- 纯渲染工具加载更快、无需 utilityProcess；代价是不能注册自有 IPC 通道（`plugin.channels` 为空）。

## 三、manifest 字段逐项说明

### 3.1 基础

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 小写字母开头，仅小写/数字/连字符，2-64 位；**= 目录名，创建后不可改** |
| `name` / `description` | string | ✅ | 桌面卡片名称与描述；可被 `app.toolOverrides.<id>` 覆盖 |
| `category` / `tags` | string \| string[] | — | 多分类 + 标签合并为 `categories[]`，卡片/搜索/侧栏全链路使用 |
| `icon` | string | — | `auto` = 用 assets/icon.svg；也支持 http(s)/data URI |
| `entryRoute` | string | — | 默认进入的菜单 id（通常是 `menus[0].id`） |
| `enabled` | boolean | — | 出厂默认启停 |
| `visibility` | string | — | `desktop` 默认上桌面 / `managed` 受控（进权限列表，用户开启后上桌面）/ `hidden` 隐藏 / `implicit` 隐式基座（永不上桌面仅被依赖） |
| `dependsOn` | string[] | — | 硬依赖：依赖工具不可用时本工具一并隐藏；默认 `[]` |
| `requiredGrant` | string | — | `tools.restricted` = 需访问密钥；空 = 公开 |
| `defaults` | object | — | 工具配置默认值，宿主启动时自动合并（key 支持点路径嵌套） |

### 3.2 菜单（`menus[]`）

| 字段 | 说明 |
|---|---|
| `id` | 小写字母/数字/连字符；传给渲染壳做页面分发 |
| `label` | 左侧菜单显示名 |
| `children` | 可选，任意层级子菜单（后台管理风格） |

### 3.3 配置形态（两选一，`configLayout`）

| 形态 | 字段 | 语义 |
|---|---|---|
| **形态 1**（默认） | `configLayout: "single"` | 单个「工具配置」菜单，进去左右布局：左栏分组导航、右栏表单、底部固定保存条 |
| **形态 2** | `configLayout: "menu"` + `configPages[]` | 「工具配置」展开二级菜单，每个二级菜单一个真实页面（页内复用左右布局），**一页可含多个分组** |

`configPages[]` 结构：`{ id, label, groups: string[] }`：
- `id` 即二级菜单 id，**必须以 `config-` 开头**（宿主据此识别配置路由）
- `groups` 引用 `configGroups[].id`；所有分组都应被某个页覆盖（无孤儿分组）
- 历史 `tabs` 值已归一为 `single`

### 3.4 配置分组（`configGroups[]`）

| 字段 | 说明 |
|---|---|
| `id` | 分组 id（形态 1 下同时是 URL section 定位值） |
| `label` | 左栏导航显示名 |
| `fields[]` | 字段数组，见下表 |

字段（`ToolConfigField`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | string | 相对 `tools.<id>` 的点路径，如 `render.strict`、`llm.temperature` |
| `label` / `hint` | string | 表单标签 / 说明文字 |
| `type` | string | `string` / `number` / `boolean` / `select` / `dir` / `file`；**路径类必须用 dir/file**（宿主提供选择对话框，禁止裸 string 手填） |
| `required` | boolean | 保存时空值拦截 |
| `devOnly` | boolean | 仅 dev 展示，打包版隐藏但保留其值 |
| `options` | {label,value}[] | select 选项 |
| `optionsSource` | string | 动态选项源（如 `upload:all` 拉全局上传 profile），避免写死 |
| `min` / `max` | number | number 边界 |
| `fallbackKey` | string | 值为空时展示该配置键的生效值 |

### 3.5 插件入口（`plugin`）

| 字段 | 说明 |
|---|---|
| `source` | `builtin`（随仓库分发）/ `external`（第三方包） |
| `main` | 主进程入口路径（内建 `src/main/index.ts`） |
| `renderer` | 渲染壳路径（内建 `src/renderer/<PascalId>Page.vue`） |
| `channels` | **工具自有通道**白名单，格式 `<id>:<name>`；工具加载失败时宿主按此注册拒绝兜底 |

### 3.6 运行时包契约（`package`）

| 字段 | 说明 |
|---|---|
| `schemaVersion` | 固定 1 |
| `version` | 工具版本 |
| `requiresHost.api` | `^1.0` |
| `requiresHost.capabilities` | 7 项宿主能力复选：`getToolSecret` / `setToolSecret` / `chat` / `listProviders` / `chatByProvider` / `listModelsByProvider` / `runLocalOcr`；**按需勾选，权限最小化** |
| `sandbox` | `utility`（默认）/ `main`（需有效签名） |
| `ipcAllowlist` | **宿主通道**白名单（`IPC_CHANNELS` 全表可选）；注意与 `plugin.channels` 是两回事 |

### 3.7 软依赖（`configDeps[]`）

`{ toolId, key, label }`：读取其它工具配置做只读展示 + 缺失预警，不做硬禁用。

## 四、代码入口契约（两条铁律）

1. **主进程入口必须 `export default` 注册函数**（或具名 `register`）：

```ts
import type { IpcMain } from 'electron'
import type { ToolHostCapabilities } from '@sshk/shared'

export default function registerToolMain(
  ipcMain: IpcMain,
  deps: { toolId: string; host: ToolHostCapabilities },
): void {
  const ch = (name: string) => `${deps.toolId}:${name}`
  ipcMain.handle(ch('ping'), () => 'pong')
}
```

2. **toolId 单一来源 = manifest.id**：渲染壳接收宿主 `:tool-id` prop 注入 `state.ts`，深层组件用 `useToolId()`（`@sshk/ui-kit`）；**源码任何位置不得硬编码工具 id**。

其它要点：
- 渲染壳只做 menu → 页面分发，业务全在 `pages/`；
- 密钥只走 `host.setToolSecret/getToolSecret`（safeStorage），明文永不入渲染层/仓库；
- 新增宿主 `window.api.*` 方法必须走 `callHostApi()`（`@sshk/ui-kit`）兜底（preload 是启动快照，dev 热更不重放）；
- 配置读写走 `window.api.config.get/set`（需在 `ipcAllowlist` 放行 `config:get/set`）。

### 4.3 应用能力消费（D53 边界铁律）

- **依赖方向唯一：工具 → 应用能力**。纯工具经 `createSafeHost`（`@sshk/ui-kit`，各工具 renderer `host.ts` 声明通道映射）**单向消费**应用能力：配置、上传、分享、LLM、safeStorage、FS 等。
- **应用本体绝不 import 工具代码**（运行时 discovery 动态加载清单/入口除外）——应用与工具之间只有 manifest 契约与宿主能力注入两条通道。
- 工具之间禁止互相 import（`check-boundaries.mjs` + ESLint `no-restricted-imports` 强制）；跨工具复用一律下沉 `packages/`（≥2 消费者；基础能力模块属应用本体例外，见总纲 §1.3）。
- 工具业务配置留 `tools.<id>.*`（D32 分层不动）；应用级参数进 `app.*`；三模块配置在 `app.modules.<moduleId>.*`（P4-8c 一次性迁移后的事实）。

### 4.4 TODO 标记约定（B4）

- 未完成项必须留在代码里并带台账编号：**`// TODO(台账#编号): 说明`**（如 `// TODO(台账#151): 等真实账号跑 V7 云链路验证`）。
- 禁裸 `TODO` / `FIXME` / `HACK`（无编号不可追踪）；完成销账时随对应批次删除该标记。
- 台账编号 = `docs/02-architecture/工具插件化需求台账.md` 行号条目（如 #151/#156），保证任何遗留项可反查到登记源头与拍板上下文。

## 五、门禁清单（`pnpm verify` 13 项）

| 门禁 | 与工具相关的检查点 |
|---|---|
| `check:structure` | 目录/分层约定 |
| `check:contract` | manifest 契约、能力与通道声明一致 |
| `check:external` | 外部包产物形态 |
| `check:boundaries` | 渲染层不得 import main 进程模块 |
| `check:preload` | `window.api` 类型与 preload 暴露一致 |
| `check:dialogs` | 所有 `el-dialog/el-drawer` 必须带**字面量**属性 `close-on-click-modal="false"` 与 `close-on-press-escape="false"`（绑定写法 `:close-on-click-modal` 不被识别，会挂 CI） |
| `typecheck / typecheck:vue / lint / test` | 常规 |

提交前 husky hook 会自动跑 `pnpm verify` + desktop build（`.husky/pre-commit`，提交直接 `git commit`，绝不 `--no-verify`）。

## 六、常见报错对照

| 报错 | 原因 / 解法 |
|---|---|
| `工具 id 非法` / `manifest.id 必须等于目录名` | id 或目录名不匹配 §3.1 规则 |
| 工具不出现 | visibility 为 hidden/implicit；或依赖不可用；或插件加载失败（看「设置 → 工具与权限」里的插件状态） |
| 通道调用被拒 | 通道不在 `plugin.channels` 或 `ipcAllowlist`；或工具被禁用 |
| `check:dialogs` 挂 CI | 弹框缺字面量禁关属性（见 §五） |
| dev 下新工具不出现 | 新增工具目录后需**重启 `pnpm dev`**（构建期 `import.meta.glob` 扫描，不支持热加载新目录） |
| 「配置」按钮灰 | 打包版需开启开发者模式 + 主进程确认源码仓库；dev 恒可用 |

## 七、开发到分发

| 阶段 | 动作 |
|---|---|
| 日常 | 改 `tools/<id>/src/**`，dev 热更即时可见；manifest 改动在「工具与权限 → 配置」表单化编辑并「保存并校验」 |
| 构建外部产物 | 配置表单「构建外部产物」或 `node scripts/build-external.mjs <id>` → `dist/page.js`（零 import）+ `dist/main.js` |
| 导出分发包 | 「导出 .sshktool」（可勾选导出前签名）或 `node scripts/pack-tool.mjs <id>` |
| 安装 | 外部包通过设置中心导入（签名 / 重复包防护见工作流规划文档） |
