## 一、定位与落点（已拍板）

- **implicit 共享包**（无菜单入口，各工具 `import` 即用），对齐 `upload-core` / 模型服务范式。
- ✅ **Q1 独立两包**：`packages/code-editor` + `packages/rich-text`。理由：Monaco / wangEditor 是重依赖（Monaco 大包 + worker 链），并入 `ui-kit` 会拖累只用基础组件的 Electron 工具；独立包按需 import，构建与体积隔离。
- ✅ **Q3 富文本统一**：所有工具共用**一个**富文本能力，不各做一套。
- ✅ **Q2 依赖一次性写入**：所有需要的依赖**统一一次性写入各包 `package.json`**，由用户自行安装（AI 不代跑安装，遵循用户级规则 #1）；**包括 md 的支持**（范围见 §五 P1，唯一剩余待拍板项）。
- ✅ **Q4 推进节奏**：R26（上传）与 R27（本能力）**先讨论定稿、确定协同方式，再一起同时开工、逐个做**。不单独起其中一条。

## 二、语言支持清单（集中注册，避免各工具重复）

| 语言 | 来源 | 当前状态 |
|---|---|---|
| html / css / js / ts / json | Monaco 内置 basic-languages | 开箱即用 |
| python / java / php | Monaco 内置 basic-languages | 开箱即用 |
| yaml | `monaco-yaml`（LSP，含校验/补全/悬浮） | **已装** (`edm-studio`)，迁移至 code-editor |
| markdown | Monaco 内置 basic-languages | 零新增依赖；是否还要富文本 md 互转见 §五 P1 |
| njk (Nunjucks) | 自定义 Monarch 或沿用 html 近似 | EDM 现为 `njk → html` 近似高亮，见 §三 |
| env | 自定义轻量 Monarch（`KEY=VALUE`）或按 shell/ini | EDM 尚未注册 |
| 富文本 | `@wangeditor/editor`（`packages/rich-text`） | 非 Monaco |

- **扩展名→语言映射表**（`languages.ts`）：`.html→html`、`.css→css`、`.js→js`、`.ts→ts`、`.json→json`、`.yaml/.yml→yaml`、`.njk→njk`、`.env→env`、`.php→php`、`.java→java`、`.py→python`、`.md→markdown`。
- **组件 `CodeEditor` props**：`path?`（自动按扩展名判语言）/ `language?` / `modelValue` / `readonly` / `dark`（随主题）/ `minimap?` / `diff?` / `schema?`（yaml JSON Schema 校验，沿用 EDM 现有能力）。各工具零配置接入。

## 三、侦察事实与必须固化的工程约束（2026-11-15 代码走读）

> 来源：`tools/edm-studio/src/renderer/{monaco-setup.ts,MonacoEditor.vue,RichTextEditor.vue}` 与 `package.json`。迁移时**原样带入**，不得重踩。

| # | 事实 / 坑 | 迁移要求 |
|---|---|---|
| F1 | `@wangeditor/editor-for-vue` 的 `latest` 是 **Vue2 包**，与 Vue3 不兼容；现有代码刻意绕开，直接用 `@wangeditor/editor` 的 `createEditor` / `createToolbar` | rich-text 包**禁止**引入 `editor-for-vue`，沿用 core API 封装 |
| F2 | wangEditor `fullScreen()` 要求 toolbar 与 textarea **父节点一致**，否则抛错；且全屏容器 `position:fixed` 无 `z-index` | toolbar 与编辑器用**同一容器 selector** 创建；CSS 补 `z-index`；**绝不** `appendChild` 把节点移出 Vue 虚拟树（曾致编辑器凭空消失） |
| F3 | `monaco-editor@0.57` 的 exports 把 `./*` 映射到 `./esm/vs/*`，worker 写成 `esm/vs/.../x.worker` 会路径翻倍，rolldown 构建期无法解析 | worker 导入**去掉 `esm/vs/` 前缀**：`monaco-editor/editor/editor.worker.js?worker`（json/css/html 同理） |
| F4 | `@guolao/vue-monaco-editor` 经 `@monaco-editor/loader` **默认从 CDN 拉 monaco**（断网不可达） | 必须 `loader.config({ monaco })` 指向本地实例 |
| F5 | `monaco-yaml` 存在 v5 `setupMonacoYaml` / v4 `yamlDefaults` 两套 API | 保留双分支兼容，避免版本漂移静默失效 |
| F6 | Monaco 多实例（隐藏 tab）曾出现「不可输入 / 内容错乱」 | 每个实例由 `path` 生成**唯一 model URI**（`inmemory://model/<path>`） |
| F7 | 根门禁 `check:latest`：外部依赖一律 `"latest"`、内部 `workspace:*`、`typescript` 例外 `6` | 新包依赖严格按此写，否则 `pnpm verify` 直接挂 |
| F8 | 根门禁 `check:structure`：所有 `package.json` 必须 `"type": "module"`；业务源码禁用 `toISOString(` | 新包骨架必备；时间统一用 `@sshk/shared/time.ts` |
| F9 | `tsconfig.base.json` 的 `"@sshk/*"` 通配 + `vitest.config.ts` 动态扫描 `packages/*/src/index.ts` | 新包**无需**改 paths / 测试配置，但必须有 `src/index.ts` 才会被 vitest 扫到 |
| F10 | `pnpm-workspace.yaml` 已处理 wangeditor 依赖链 `es5-ext`、monaco 间接引入的 `dompurify` 漏洞（`>=3.4.17`） | 新增 `ssh2` 等含 optional native 依赖时需复核 `allowBuilds`（见协同方案 B0） |

## 四、与现有 EDM 代码的关系（迁移复用）

- EDM `MonacoEditor.vue` + `monaco-setup.ts` → 迁入 `packages/code-editor`，EDM 改为 `import { CodeEditor } from '@sshk/code-editor'`。
- EDM `RichTextEditor.vue` → 迁入 `packages/rich-text`。
- EDM 侧四个直接依赖（`monaco-editor` / `monaco-yaml` / `@guolao/vue-monaco-editor` / `@wangeditor/editor`）移除，改为两个 `workspace:*` 包引用。
- **顺序约束**：EDM 同时是 R26（图片/文件上传）与 R27（编辑器迁移）的迁移对象，须先做纯组件替换、再注入上传实现，详见协同方案 B6→B7。
