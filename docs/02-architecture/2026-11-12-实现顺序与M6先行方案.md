## 一、实现顺序（覆盖原 M0→M7 顺序）

```
M0 → M1 → M2 → M3 → M7 → M6 → M4 → M5
```

| 位次 | 阶段 | 为什么排这里 |
|---|---|---|
| 1 | M0 骨架 | 地基 |
| 2 | M1 应用壳 | 四层 UI、配置、目录迁移 |
| 3 | M2 发布更新 | 早建立可安装产物，便于边做边验 |
| 4 | M3 公共底座 | **必须先于任何业务工具**（需求 15） |
| 5 | **M7 模型与 OS 能力** | 右键/托盘/文件选择/上传能力是 M6 的前置；模型网关与业务解耦 |
| 6 | **M6 Badge Studio** | **近期最急的业务**，先用现有 `juice-email-cli` 产物跑通闭环 |
| 7 | M4 EDM Studio 数据与模板 | 品牌树、模板片段版本 |
| 8 | M5 EDM Studio 邮件列表 | 最后接上，复用已稳定的 M3/M6 能力 |

## 二、依赖冲突校验（顺序是否走得通）

| 原依赖 | 冲突 | 解法 |
|---|---|---|
| M6 原依赖 M5 的 `final.html` | M4/M5 还没做 | **改走「上传 / 选择外部 HTML」通道**，用 `juice-email-cli` 已生成的 HTML（见 §3） |
| M7 原依赖 M2、M4 | M4 未做 | M7 只做 `llm-gateway` + `model-console` + OS 能力（右键/托盘/文件对话框），**摘掉对 EDM 业务的依赖** |
| M6 依赖 M3 | M3 已在前 | ✅ 天然满足 |
| M4/M5 依赖 M3 | M3 已在前 | ✅ 且可复用 M6 已验证的 `html-dom` / `capture` |

> 结论：顺序可行，关键是把 M6 的输入从「edm-studio 产物」切换到「外部 HTML」，并把 M7 的业务依赖摘干净。

## 三、M6 独立可跑：补齐的空白功能（重点）

原设计「邮件 HTML 二选一：① 从 edm-studio 已生成产物按 mailId 选 ② 上传外部 html」。M4/M5 未做时通道 ① 不可用，补齐如下：

| # | 补充功能 | 说明 |
|---|---|---|
| 1 | **上传 HTML 文件** | 多选 / 拖拽，支持 `.html` / `.htm` |
| 2 | **粘贴 HTML 源码** | 不落盘也能临时生成 |
| 3 | **最近使用的 HTML 列表** | 本地历史（记录路径 + hash + 上次使用时间，北京时间），支持反复使用、置顶、移除 —— 呼应「产物可能被多次使用」 |
| 4 | **从 juice-email-cli 输出目录选择** | 可配置一个「常用 HTML 目录」，一键列出其中 HTML；不做命令耦合，只读文件 |
| 5 | **badge 属性缺失兜底**（关键） | `juice-email-cli` 现有产物大概率**没有** `data-edm-badge` 属性。补：① 属性名可配（已有）；② 「批量补属性」预处理页：按 URL 命中后列出「命中但未带属性」的 `<a>`，用户勾选后**在 badge 副本里补属性**，原文件绝不动；③ 高级规则支持按 CSS 选择器指定；④ **默认仍严格守住门控**：没属性不打 badge |
| 6 | 四种数据源上传 + 模板下载 | 图片/excel/csv/json，csv/xlsx/json 空模板（D10 已定） |
| 7 | URL 归一 + 未匹配手动配对 | 去 utm/去 #/末尾斜杠/query 排序；一对多全部打标 |
| 8 | badge 副本 + 覆盖式海报产物 | `badged.html` + `poster.png`，直接覆盖不留历史（D19） |
| 9 | 海报列表全套按钮 | 新增/编辑/删除/复制海报/复制代码/导出/重新生成/分享链接 |
| 10 | 局域网分享 | M7 已先做完，M6 直接复用 |

## 四、与 juice-email-cli 的衔接（不做代码耦合）

```
juice-email-cli 生成 final.html（现有工具，命令行）
        ↓ 上传 / 从常用目录选择
badge-studio 选择或上传邮件 HTML
        ↓ 上传点击统计 csv / xlsx / json / 图片
配置 badge 属性名 · URL 归一 · 数值列(Clicks) · 海报宽度
        ↓ 点击生成
badged.html（独立副本，只写给副本）  +  poster.png（海报长图）
        ↓ 海报列表：导出 / 复制代码 / 分享链接
```

- **badge-studio 不 import、不调用 juice-email-cli**，只读它产出的 HTML 文件。
- 原 HTML 全程只读；badge 副本与海报独立覆盖式生成，互不干扰（需求 7 / D19）。
- M4/M5 做好后，通道 ①（按 mailId 从产物注册表选）自动补上，两条通道并存。
