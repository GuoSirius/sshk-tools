# 文件选择弹框通用化与图片库迁移（file-picker）

> 来源：用户 2026-11-17「图片库弹框提取复用，EDM 后续传图可用，扩展支持任意文件；选中数量/类型/格式/确认后行为由使用方传参」。
> 状态：**已落地**（`f015755` 主体 + `be41919`/`97cefff`/`afd3bbe` 交互修复，全量门禁绿、55+ 测试全绿）。

## 一、动机与定位

| 项 | 内容 |
|---|---|
| 动机 | rich-text 的 ImageLibraryDialog（上传 + 图床选择插入）在 EDM 等工具同样可用；且后续要支持任意文件（文档/视频），不应绑死在富文本包里 |
| 定位 | `@sshk/file-picker` 通用文件选择弹框包：**上传 + 已有库选择 + 确认交付**三段式，用途（插图/插文件/其他）完全由使用方决定 |
| 契约红线 | 沿用 C2：**file-picker 不 import upload-core**，桥接接口（sources/list/listDirectories/upload）由工具侧注入；类型定义在 `src/types.ts` 自持 |

## 二、参数契约（最大化通用 + 定制点全覆盖）

| 参数 | 默认 | 说明 |
|---|---|---|
| `mode` | 必传 | `'image' \| 'file'`：接受类型、空态文案、卡片形态（缩略图/文件卡）随模式切换 |
| `library` | 必传 | 桥接接口：`sources / list / listDirectories? / upload`（工具侧注入，见 C2） |
| `open` / `stateKey` | 必传 | v-model 开关；设置隔离键（localStorage `sshk:file-picker:<stateKey>`，**回落读旧键 `sshk:rich-text:image-library:<stateKey>`** 保住老用户已存来源/目录） |
| `title` | mode 推导 | 缺省按类别「图片库」「文档库」「代码库」「文件库」，应用方可传 |
| `accept` | `accept > allowedExts 推导 > kind 类别默认` | 文件选择框接受类型（提示性过滤，拖拽可绕过；强制拦截靠 allowedExts/kind）。allowedExts 推导为**扩展名 join**（如 `.mp3,.mp4,.pdf,.js`），按扩展名匹配不依赖 MIME 映射，规避 application/pdf / x-pdf / octet-stream 等 MIME 变体；需要 MIME 提示可显式传 accept 覆盖 |
| `allowedExts` | 未设置 | 自定义扩展名白名单（如 `['.md', '.pdf']`）：非空时**替代** kind 类别白名单，上传拦截（含拖拽）与列表前端过滤双重强制，选择池条目只来自这两处故自然被覆盖；归一化小写/补点，无文件名宁缺勿滥。与 `mode` 的配合：mode 决定服务端列取范围（kind 透传底层），allowedExts 在该范围内二次收紧——白名单是五类之外的扩展名组合时，mode 应配 `'document'` 或 `'all'`，否则列取范围先被 kind 卡死 |
| `multiple` / `maxCount` | false / 0（不限） | 单选=新选替换旧选；多选按容量拦截 |
| `maxUploads` | 0（不限） | 本次打开弹框累计上传文件数上限（进行中+成功计入，失败不占额度）；与 maxCount 独立，可「传 10 选 20」分别控量 |
| `maxSize` | 0（不限） | 单文件字节上限（组件侧快速拦截，真正校验在 Upload Service） |
| `naming` / `conflict` | `hash` / `hash` | 命名：hash=内容寻址（现状逻辑）/ original=保留原名；冲突：hash=追加 -hash8 / overwrite=覆盖。核心在 `resolveUploadName()` |
| `confirmText` | mode 推导 | 确认按钮文案（「插入所选」/「确认选择」） |
| `initialTab` / `defaultTarget` | `upload` / 空 | 打开默认页签；无已存设置时预设桶/目录 |
| `resolveSrc` | 原样 | 条目 URL 展示转换（localres 形态由应用方注入） |
| emits | `update:open` + `confirm(items)` | 确认只交付条目并收尾清池，**不决定用途** |

## 四、kind 线程（文件模式列取）

`listImages` 全链加 `kind?: FileKind`（**缺省 `image` 保持历史行为**）。类别体系 2026-11-17 扩展为四类，
统一定义在 `@sshk/shared/src/file-kinds.ts`（列取过滤与弹框默认 accept 共用同一份白名单，不漂移）：

| kind | 类别 | 过滤口径 |
| --- | --- | --- |
| `image` | 图片库（历史行为） | IMAGE_EXTS：png/jpg/jpeg/gif/webp/bmp/svg/ico/avif |
| `document` | 文档库 | DOCUMENT_EXTS：pdf/office 系列/txt/md/csv/odf/wps 等 21 种 |
| `code` | 代码库 | CODE_EXTS：js/ts/vue/py/go/rs/c 系/sh/sql/json/yaml/web 三件套等 40+ 种 |
| `video` | 视频库 | VIDEO_EXTS：mp4/mov/avi/mkv/webm 等 16 种（.ts 归代码类不重复收） |
| `all` | 文件库（全部文件） | 不过滤 |

历史值 `'file'` 在 main 侧 `normalizeListKind` 归一为 `'all'`（桥接/组件不再产生该值）。
`isKindFileName(undefined)` 恒 false——调用方必须显式补缺省（Provider 内 `kind ?? 'image'`），宁缺勿滥。

```
FilePickerDialog list(kind=mode)
  → 桥接 host.upload.listImages({ ...req, kind })
  → IPC upload:images:list（UploadListRequest.kind，normalizeListKind 归一）
  → main readonlyList / service.listImages
  → Provider（cloud/local/remote）.listImages（kind ?? 'image'）
      image/document/code/video：isKindFileName 按白名单过滤（shared 单一来源）
      all：不过滤，列全部文件
```

弹框侧（FilePickerDialog）按 mode 同步推导：默认标题（图片库/文档库/代码库/视频库/文件库）、
页签文案（上传图片/上传文档…）、默认 accept（FILE_KIND_ACCEPT）、上传类别拦截（拖拽/选择
不属于该类别的文件直接跳过并提示）。

## 五、交互沉淀（实测坑与定稿行为）

| 项 | 结论 |
|---|---|
| 目录级联取语义（三种源统一） | 选中父目录 = 列出自己 + 所有层级子目录的图片（递归，带上限）；目录下拉为**懒加载级联**：点文字下钻、点圈选中即回显关闭（`checkStrictly` + `emitPath:false`） |
| **坑⑰：EP cascader `leaf` 字段钉死** | 节点数据带显式 `leaf` 字段时 `isLeaf` 直接取值、不走「已加载且无子→叶子」推断；写死 `leaf:false` 会让空目录点文字永远不能选中。**不要写 leaf 字段**，让 EP 自动推断；点下钻发现无子目录时手动 `handleCheckChange(node, true, false)` 完成首次点击即选中（`dirPanelGen` 代次守卫防在途竞态） |
| **坑⑱：cascader 挂载早于数据竞态** | EP 的 `config` watch 带 `immediate`，挂载瞬间即触发根节点懒加载；若此时激活源未就绪（弹框打开流程异步未完成）而 `resolve([])`，根节点被**钉死成已加载空态**，之后展开不再重拉——必须换源重挂才能拉出（用户反馈「首开 No data 无 loading / 必须切一次源」）。修复：无激活源且 open 流程未完时 `await restored` 再拉，等待期 EP 自带 loading；弹框已关则放弃 |
| 上传区与卡片区合并布局（2026-11-20 拍板） | 上传页签的「拖拽上传横条」取消，改为 `thumb-grid` 网格第一张「添加」卡（+ 图标 / 点击或拖拽{类型} / 可多选），与上传任务卡、已上传卡同排；空态只显示这张卡，有文件后自然连成片。长规则收进卡片 `title` 悬浮，卡内只放短词；点击/拖拽入口不变（仍共用 `pickFiles`/`onDrop` → `handleFiles`） |
| 确认动作沉底 | 继续上传 / 插入所选在 footer 与关闭同行，关闭固定最右（2026-11-17 拍板） |
| 删除 vs 移除图形语义 | 右上角 18px 悬浮 icon（毛玻璃暗底、hover 红色填充）：**垃圾桶=从本次上传删除**，**✕=取消已选（不动文件）**，避免同图标歧义 |
| 复制链接 icon | 缩略图名行尾，cell hover 时浮现（`copy-link`） |
