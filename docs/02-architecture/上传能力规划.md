# 上传能力规划（R26，2026-11-15 定稿讨论稿）

> 类比模型（Model）范式：一次实现 + 一处配置 → 应用本身可用 + 所有工具只选即用。
> 上传（Upload）按同一思路做成**应用级共享能力**：一次实现 + 多 profile 配置，所有工具直接复用，不各做一套。

## 一、关键设计决策（本次细化，已拍板）

| 上传目标 | 配置形态 | 工具侧使用 |
|---|---|---|
| **本地目录** | 极简：仅一个**默认目录**（全局） | 工具可单独覆盖本地位置；无需 profile |
| **FTP / SFTP（合并为「远程 profile」）** | **多个命名 profile**，每个独立连接信息（`protocol` 区分 ftp/sftp；主机/端口/用户/密码/远程目录/被动模式） | 工具选某个 profile + 覆盖「远程目录」等非固定信息 |
| **云存储** | **多个命名 profile**，可同云多账号（如阿里云 OSS 主账号 / 子账号）、不同云混排 | 工具选某个 profile + 覆盖「bucket / 文件目录 / 位置」等个性化项 |

> 核心变化：**从「单一 FTP + 单一云」改为「远程(ftp/sftp) 多 profile + 云多 profile」**。连接信息在全局一次性预设，工具只选 profile 并填少量个性化字段。

## 二、数据模型

### 2.1 全局上传配置（app settings，由「上传配置工具」管理，密钥走 safeStorage）

```yaml
upload:
  local:
    defaultDir: "~/edm-out"            # 单一默认本地目录
  remote:                              # FTP / SFTP 合并为「远程 profile」，protocol 区分
    profiles:
      - id: ftp-prod
        name: "生产 FTP"
        protocol: ftp                  # ftp | sftp
        host: "192.168.1.10"
        port: 21                       # ftp 默认 21，sftp 默认 22
        username: "..."
        password: "<safeStorage>"
        remoteDir: "/edm/out"
        passive: true                  # 仅 ftp 生效
      - id: sftp-bastion               # 可任意增删，同结构 protocol: sftp
        ...
    defaultId: ftp-prod
  cloud:
    profiles:                          # 多个命名云配置，可同云多账号
      - id: oss-main
        name: "阿里云 OSS-主账号"
        provider: aliyun-oss
        region: "oss-cn-hangzhou"
        endpoint: "oss-cn-hangzhou.aliyuncs.com"
        bucket: "edm-prod"
        accessKeyId: "..."
        accessKeySecret: "<safeStorage>"
        baseUrl: "https://cdn.example.com"
      - id: oss-sub                    # 同云不同账号
        name: "阿里云 OSS-子账号"
        provider: aliyun-oss
        ...
      - id: cos-marketing
        name: "腾讯云 COS-营销"
        provider: tencent-cos
        ...
    defaultId: oss-main
```

### 2.2 工具级 configGroup `upload`（各工具 SettingsPage 渲染）

```yaml
upload:
  targetType: "cloud"        # local | remote | cloud
  profileId: "oss-main"      # 选中全局 profile；省略则用对应 defaultId
  overrides:
    remotePath: "/2026/campaign"   # 远程(ftp/sftp) 目录覆盖
    bucket: "edm-prod-2"          # 云 bucket 覆盖
    prefix: "mail/"                # 云对象 key 前缀 / 目录
```

## 三、Provider 架构（Upload Service 内核）

- **位置**：`packages/upload-core`（新建共享包，与 `llm-gateway` 平级），由桌面端 main 进程持有 provider 实例（生命周期同模型服务）。
- **暴露方式**：main 进程经 IPC 暴露 `upload:single` / `upload:batch`（带进度事件），渲染层经 `api()` 调用，不直接持密钥。
- **统一能力**：单文件 / 批量上传（**并发控制**）、进度回调、失败重试、格式白名单 + 大小上限校验（**全局默认 + 工具可收紧**）、密钥运行时从 safeStorage 解析。

```ts
interface UploadProvider {
  type: 'local' | 'remote' | 'cloud'
  upload(file: LocalFile, ctx: UploadContext): Promise<UploadResult>   // { url, key/remotePath }
  uploadBatch(files: LocalFile[], ctx: UploadContext, opts?: { concurrency?: number }): Promise<UploadResult[]>
}
```

- **Provider 实现**：
  - `LocalUploadProvider`：写本地目录，返回本地 / file URL。
  - `RemoteUploadProvider`：用 `basic-ftp`(ftp) / `ssh2`(sftp)（成熟包），按 profile 的 `protocol` 路由连接。
  - `CloudUploadProvider`：按 provider 路由官方 SDK——`ali-oss`(阿里云)、`cos-nodejs-sdk-v5`(腾讯云)、`@aws-sdk/client-s3`(AWS)、`qiniu`(七牛)；首期落地阿里云 OSS，其余留抽象扩展点。

## 四、上传配置工具

- 新建 `tools/upload-config`（或并入「工具配置」页的全局段），管理：本地默认位 + 远程(ftp/sftp) 多 profile + 云多 profile + 默认 profile 选择。
- 密钥输入走 safeStorage，绝不落明文（对照 #18 密钥红线）。

## 五、工具接入方式

- **全局预设 + 工具覆盖**：上传 profile 为全局预设（一次配置全工具复用），各工具 `tool.manifest.json` 增 `upload` configGroup（`targetType` / `profileId` / `overrides`），运行时从 Upload Service 取对应 provider 执行。
- 迁移对象（接入阶段）：EDM `ImageField.vue`（本地→dataURL 改为走共享上传，回填服务端 URL）、富文本图片、EDM 图片上传；`sample-schema.ts` 的 `upload` 字段（R15.3）正式生效。

## 七、已拍板项（2026-11-15 用户确认）

1. ✅ **FTP 与 SFTP 合并**：合并为「远程 profile」，用 `protocol: ftp|sftp` 字段区分（少一套 UI）。见 §2.1 `remote:` 与 §三 `RemoteUploadProvider`。
2. ✅ **Upload Service 落点**：新建独立包 `packages/upload-core`（职责清晰、可单测，与 `llm-gateway` 平级）。
3. ✅ **全局配置 vs 工具内配置**：上传 profile 为**全局预设**，工具仅选 `profileId` + 覆盖 `overrides`（path/bucket/prefix）；一次配置全工具复用。
4. ✅ **校验策略**：**全局默认**（格式白名单 + 大小上限）+ **工具可收紧**（工具级 configGroup 可设更严的 whiteList/maxSize）。
