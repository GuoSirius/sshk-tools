# 模块规范：ESM 优先，兼容 CommonJS

- 状态：已定（用户 2026-11-12 21:52 追加）
- 版本：v0.1
- 最后更新：2026-11-12 21:52（北京时间）
- 关联：选型稿 §2.2 进程边界、数据契约 §1、M1 应用壳
- 决策编号：**D23**

---

## 一、原则

| 项 | 约定 |
|---|---|
| 源码 | 一律 **ESM**（`import` / `export`），所有 `package.json` 声明 `"type": "module"` |
| 包对外 | 条件导出同时提供 `import`(ESM) 与 `require`(CJS)，`types` 指向 `.d.ts` |
| 应用入口 | Electron 主进程 ESM（Electron 28+ 支持），入口 `.mjs` |
| **preload** | **产物必须 CJS（`.cjs`）** —— `sandbox: true` 下 preload 由 `require` 加载，不支持 ESM import。源码仍写 ESM/TS，由 electron-vite 构建成 `out/preload/index.cjs`。**这是硬性约束，不是偏好** |
| 渲染进程 | ESM（Vite / Vue SFC） |
| 脚本与配置 | 默认 `.mjs` / `.js`(ESM)；确需 CJS 时用 **`.cjs` 后缀**，不改根 `type` |
| 引入 CJS 依赖 | `createRequire(import.meta.url)`，禁止把整个包降级为 CJS |

> 与三条安全红线不冲突：`nodeIntegration:false` + `contextIsolation:true` + `sandbox:true` 保持不变；只是 preload 这一层按 Electron 的要求用 CJS。

## 二、分层落地

| 位置 | 格式 | 说明 |
|---|---|---|
| `packages/*/src/**` | ESM TS | 内部源码，纯 ESM |
| `packages/*/package.json` | `type: module` + `exports` 条件导出 | M1 构建链落地后产出 `dist/index.mjs` + `dist/index.cjs` |
| `apps/desktop/src/main/**` | ESM TS → `.mjs` | 主进程；ESM 下用 `import.meta.url` + `fileURLToPath` 取路径 |
| `apps/desktop/src/preload/index.cjs` | **CJS** | 只做 `contextBridge.exposeInMainWorld` 白名单转发，不放业务逻辑 |
| `apps/desktop/src/renderer/**` | ESM (Vue SFC) | Vite |
| `scripts/*.mjs`、`eslint.config.js`、`commitlint.config.js` | ESM | 工具链 |
| `.git/cph/*` | `#!/bin/sh` | 与模块系统无关 |

## 三、条件导出模板（M1 构建链落地后启用）

```jsonc
{
  "type": "module",
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    }
  }
}
```

**M0 现状**：`packages/shared` 仍是 TS 源码直引（`exports: { ".": "./src/index.ts" }`），由 Vite / Vitest 直接编译，**暂未声明 `require` 条件** —— 因为还没有构建产物，声明一个指向不存在文件的 CJS 入口只会让 `require()` 直接失败。M1 引入构建链后按上表切换，届时同步补 `dist/index.cjs` 与 `.d.ts`。

## 四、校验

| 检查 | 落地 |
|---|---|
| 所有 `package.json` 为 `"type": "module"` | ✅ `scripts/verify-structure.mjs`（M0 已加） |
| ESLint / tsc 按 ESM 解析 | ✅ `eslint.config.js` + `tsconfig.base.json`（`module: ESNext`） |
| preload 必须 `.cjs` | ⏳ M1 应用壳落地时补进结构检查 |
| 条件导出双格式可 `import` 也可 `require` | ⏳ M1 构建链 + 冒烟测试 |

## 五、常见坑

| 坑 | 处理 |
|---|---|
| sandbox preload 用 ESM → 加载失败 | preload 固定 `.cjs`，只做白名单桥接 |
| ESM 里直接 `require()` | `createRequire(import.meta.url)` |
| ESM 里 `__dirname` / `__filename` 不存在 | `import.meta.url` + `fileURLToPath` |
| 双格式包 dual package hazard（两份模块实例） | 状态单例放主进程，包模块作用域不存可变全局 |
| `verbatimModuleSyntax` 下要产 CJS | 构建阶段用独立 tsconfig（`module: CommonJS`）产出 `.cjs`，不改源码 |
| 第三方包只有 CJS 入口 | `createRequire` 或动态 `import()`，不因此把项目改成 CJS |
