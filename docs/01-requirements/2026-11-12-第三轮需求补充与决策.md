## 1 · D10 重新定义

> 原话：用户上传的格式有**图片、excel、csv、json** 这几种，然后配合**上传或者选择的（edm 工具已经生成好的）html**，最后生成。

**结论**：D10 不再是「点击数据来源格式」这一问（v0.1/v0.2 的理解），而是**输入组合的定义**：

| 输入 | 选项 |
|---|---|
| 数据源（可多文件） | 图片 / excel(xlsx) / csv / json，四种都支持 |
| 邮件 HTML（二选一） | ① **选择** edm-studio 已生成好的产物；② **上传**外部 html |
| 动作 | 点击生成 → badge 注入 → 海报 |

配套保留：csv/xlsx/json **空模板下载**（第二轮需求 16）、图片 OCR 后**人工校对页**、未匹配链接手动配对。四种来源统一归一为 `LinkStat[]`，后续逻辑只写一次。详见选型稿 §4.5 / 数据契约 §6 `DatasourceUpload`。

## 4 · 时间规范（新需求）

> 原话：所有时间都是采用**北京时间**，无特殊情况不得使用 utc。

| 项 | 约定 |
|---|---|
| 时区 | Asia/Shanghai（UTC+8），**不使用 UTC** |
| 存储格式 | ISO 8601 带 `+08:00`，如 `2026-11-12T21:08:28+08:00` |
| 统一工具 | `packages/shared/time.ts`（dayjs + timezone），`now/format/parse/toFileName` |
| 禁令 | 禁 `new Date().toISOString()`（输出 UTC）、禁裸 `Date.now()` 入库；ESLint 拦截 |
| 覆盖 | 实体时间戳、`exportedAt`、changelog、zip 文件名、目录迁移记录、token 有效期、日志、界面展示 |
| 外部数据 | 邮件平台 csv 里的 UTC 时间 → 入口转北京时间再入库 |
| 系统值 | fs 的 mtime/ctime 是 epoch，展示层转换 |

⚠️ **推翻**数据契约 v0.1「存储用 UTC，展示转本地」的写法，已改为一律北京时间。

## 5 · 产物目录自定义与迁移（新需求）

> 原话：产物路径最好能够通过应用进行自定义设置，如果使用中途修改目录，则把旧目录的**数据**同步到新目录，成功后删除旧目录数据即可。

| 项 | 方案 |
|---|---|
| 配置项 | `app.outputDir`（应用配置 → 存储），`null` = 默认 `userData/sshk-data` |
| 推荐范围（待确认 D21） | 只搬 `outputs/` + `assets/`；`settings`/`secrets`/NeDB `db/` 留 `userData` |
| 迁移 6 步 | 预检（可写/空间/非子目录/非系统目录）→ 停写排队 → 复制到 `<newDir>/.migrating/` 并记 checksum → 校验（文件数/字节/抽样 hash/可打开）→ 原子切换配置与路径映射 → 清理旧目录 |
| **清理红线** | **绝不递归删除用户目录本身**（用户可能设在桌面/文档/下载/共享盘根）；只按迁移清单逐个删应用自有文件，不做 `rm -rf`；二次确认列出路径与数量；默认延迟到下次启动复核后再删；删除失败不回滚已成功的迁移，只记待清理清单 |
| 联动 | 导入导出 zip 内**全相对路径**，导入到 B 机重映射到 B 机 `outputDir`，不带 A 机绝对路径；覆盖式产物（需求 17）与分享服务（D15）随 `outputDir` 切换 |
| 界面 | 应用配置→存储：当前目录/占用/文件数/更改/进度/校验/历史/待清理；StatusBar 常显当前产物目录 |

见选型稿 §2.5 / 数据契约 §8。
