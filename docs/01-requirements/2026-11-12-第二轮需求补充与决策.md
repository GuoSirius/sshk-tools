## 四、一键导入导出（需求 6，本轮最大新增）

场景：A 机装了应用 → 配了主题色、是否自动升级、右键生成工具，创建了自定义模板和片段 → **导出成一个 zip**；B 机装好应用 → **一键导入** → 拥有 A 机 100% 的使用体验。

导出范围明确包含：系统配置、邮件模板和片段、**已经生成的邮件**等；要求「等同于两台电脑一模一样」。

> 方案见选型稿 §2.3 / 数据契约 §4。已识别两个无法自动迁移的例外：模型密钥（加密绑定机器）与操作系统级授权（右键菜单注册需在 B 机重新执行一次），在导入完成页显式引导。

### 5.2 EDM Studio

| # | 需求 | 要点 |
|---|---|---|
| 7 | 入口 | 桌面卡片进入后**首先展示邮件列表**；为空则提示去创建邮件 |
| 8 | 邮件管理按钮 | 新增 / 编辑 / 删除 / **复制邮件**（用于创建另一封）/ **复制代码**（渲染+juice+压缩后的最终代码）/ **导出**（三种 html：组装好未 juice 压缩、已 juice、已压缩最终）/ **复制访问链接**（指向最终压缩 html，供他人查看是否有需调整）/ **重新生成**。允许补充其他按钮 |
| 8 | 批量 | 删除、导出等可批量的都在头部加批量逻辑 |
| 8 | 多选 | **支持分页、过滤后继续选择，之前的选择不丢失** |
| 8 | 表格布局 | 顶部操作、底部分页、中间表格区撑满；若滚动**仅中间表格区滚动**；后续同类需求一律照此 |
| 9 | 模板管理 | 见下 |
| 10 | 片段管理 | 「参考模板管理的需求，整理一下」→ 已对齐整理，见选型稿 §4.4 对照表 |

**模板管理（需求 9）拆解**

| 维度 | 要求 |
|---|---|
| 按钮 | 新增 / 编辑 / 复制 / 删除，且**区分系统模板与自定义模板** |
| 模板定义 | 含基本框架、结构的代码，**包括但不限于完整 html 结构、css 样式（内联 / 本地引入 / 外链引入）** |
| 基本信息区 | 名称、描述等基本信息的维护与更新 |
| 数据编辑区 | 需要绑定数据时**让用户填写示例数据**，方便其他人员提前预览、知道该用哪个模板 |
| 代码区 | 代码维护、编辑、保存、**实时预览（可关闭）** |
| 保存分支 | 复制后保存要区分「**存为新版本**」还是「**存为另一种模板**」；保存后要知道属于**哪个品牌、哪个版本** |
| 跨品牌 | 存为另一种模板时**允许跨品牌**（复制 A 品牌模板，改完存成 B 品牌模板） |
| 危险操作 | 删除等一律**二次确认** |
| 区域数 | 基本上三个区域：基本信息 / 数据编辑区 / 代码区（含可关闭的实时预览） |

### 5.3 数据组织（需求 13，领域模型重构）

```
品牌 Brand（elabscience / procell）
├── 模板（模板A / 模板B）── 模板版本（模板A-v1 / v2）
└── 片段（片段A / 片段B）── 片段版本（片段A-v1 / v2）
```

| 规则 | 说明 |
|---|---|
| 共享范围 | **同一品牌下的所有模板可共享该品牌下的每个片段**（例：模板 A-v1 可用片段 A-v1，也可用片段 B-v2） |
| 取决于片段配置 | 片段内可配**黑白名单**，**黑名单优先** |
| 名单对象 | 名单中是对应的模板（原文举例「片段 A-v1 配置黑名单 模板 A-v1」，写的是版本 → 粒度歧义已列 D14） |
| 语义 | 配置黑名单 → 该模板不能用此片段；配置白名单 → **剔除黑名单后**只有白名单模板可用；**黑白名单都留空 = 都可以用** |

## 六、D10 的大白话重述（你说没懂）

v0.1 的 D10 问的是：**「链接 + 点击次数」这份数据，业务同事到底以什么形式交给工具？**

| 可能形式 | 工具要做什么 | 代价 |
|---|---|---|
| 平台导出 csv / xlsx 表格 | 直接解析表头，读 url 和点击数 | 低、准确 |
| 只有统计**截图**（图 2/3 就是） | 得 OCR 识别表格文字和数字 | 高、数字易认错 |
| 手工录入 | 做个表单 | 中 |

它决定要不要做 OCR、解析层复杂度多高。你 Q5 回答「平台可以导出 csv/xlsx」，所以 D10 已定：**主通道 csv/xlsx，不做 OCR 主力**；但需求 16 仍要求支持上传图片，因此图片保留为兜底（OCR → 人工校对页）。

## 八、开放问题（需求 19）

> 「大模型是否也可以作为一个工具呢？用户可以进行相关的配置，这是我的想法，你怎么看呢？」

回答见选型稿 T8：**建议拆两层** —— `packages/llm-gateway`（应用级能力，全局配置与密钥）+ `tools/model-console`（工具级可视化配置、连接测试、对话调试、用量日志）。理由是模型能力属横切关注点，只做成一个工具会逼其他工具跨工具耦合，违反需求 15。是否新增该工具列为 **D16** 待拍板。
