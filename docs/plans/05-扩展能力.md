## 五、X5 构建裁剪（Q3 衍生候选 → 用户 2026-11-16 拍板选 A，已实现）

### 背景
你原以为分发白名单能"构建时只打选中的工具"。实际白名单只控运行时可见性，构建永远全量。若确实想要"按选择打包、缩小安装包"，是新能力：

| 方案 | 做法 | 代价 |
|---|---|---|
| A 白名单裁剪构建（✅ 已实现） | 打包前读 `SSHK_BUILD_TOOLS=工具id1,工具id2` → 依赖闭包（c 被 a 依赖则 c 自动搭进去）→ ① define 注入 main/renderer 发现逻辑按名单过滤；② stub 插件把未选工具全部模块替换为空导出（真实代码不进 bundle）；③ 名单落盘 `.build-selection.json`，`electron-builder.config.cjs` 据此裁 extraResources | 单点实现于 electron.vite.config + 发现逻辑，electron-builder yml 因此迁移为 config.cjs |
| B 维持现状 + 文档澄清 | 构建全量，白名单只管可见性 | 零成本；安装包体积偏大（默认仍走 B：不设环境变量 = 全量） |

### 落地细节
- 选择解析：`apps/desktop/src/main/builtin-selection.ts`（纯函数 + 单测）：parse（去重、all/*/空=全量）→ 依赖闭包（环容忍、未知依赖交给运行时 dep-missing、未知 root 直接报错列出可用 id）
- 打包配置：`electron-builder.yml` → `electron-builder.config.cjs`（唯一动态点是 extraResources 的 TOOL_ASSETS 表按名单过滤；其余键与原 yml 逐字对应）
- 使用：`SSHK_BUILD_TOOLS=edm-studio,badge-studio pnpm dist`（或 pnpm local / release；**构建期读 .env，真实环境变量优先**，2026-11-17 修复此前仅读 process.env 导致 .env 配置不生效）
- 构建期控制台打印名单与闭包拉入项；`.build-selection.json` 已 gitignore
- **可见性语义（用户 2026-11-17 定稿）**：未指定=全量打包、按各工具可见性配置展示；指定=roots+依赖闭包入包，roots 按可见性配置展示，**pulledIn（依赖拉入）忽略一切可见性配置，任何位置（桌面/工具管理）强制不可见**——目录裁决 `resolveToolCatalog` 新增 `forcedHidden` 输入（visible/manageable=false、serviceable 保持 true 让依赖链不受影响）
- **SSHK_APP_AUTO_UPDATE=0 分发禁更**：打包版无 .env，构建期把取值注入 `__SSHK_APP_AUTO_UPDATE_DISABLED__` define，与运行时 env 双保险任一为 0 即禁用

### 构建期烤入 env + 覆盖白名单（用户 2026-11-18 拍板）

webpack 式「.env 字面量进包」的通用化，env 分两层语义：

| 层 | 机制 | 覆盖规则 |
|---|---|---|
| 烤入默认值 | 构建期把 .env 中声明的 `SSHK_` 前缀键整批注入 `__SSHK_BAKED_ENV__` 字面量（仅主进程 bundle），打包版没有 .env 也能读到构建时取值 | 默认**不允许**本机同名环境变量覆盖 |
| 运行时定制入口 | `SSHK_APP_OVERRIDABLE`（.env 声明，逗号分隔键名）列出允许覆盖的键 | 本机 env 优先，回落烤入值；**白名单自身永远锁死**（防本机给自己授权） |
| 未烤入键 | .env 未声明的键走运行时 `process.env` | 本机可设可不设（行为不变） |

- 取值统一入口（`packages/shared/src/baked-env.ts`，按需选用）：`getEnv(key)` 原始值；`getEnvStr(key, fallback)` trim + 空白回落；`getEnvBool(key, default)` 开关三态（'1'/'true' 开、'0'/'false' 关、其它/未设置取 default）；`getEnvHas(key)` 是否设置非空白值。main 侧运行时读取已全部走这套入口
- 烤入黑名单：`SSHK_BUILD_SIGNING_KEY` / `SSHK_BUILD_SIGNING_ROTATE`（构建专用，烤入产物等于泄漏私钥）；只注入主进程，渲染层不烤（无本机 env 可言且防敏感值进渲染 bundle）
- 门禁：`check:env` 扫描模式新增 `getEnv('KEY')`，与 `process.env.X` 同等对待契约校验

### 渲染层加载通道统一：app://（用户 2026-11-18 拍板「必做」）

| 环境 | 加载方式 | 说明 |
|---|---|---|
| 打包版 | `app://renderer/index.html`（**始终**，不受 env 控制） | file:// 是 opaque origin，fetch/CORS/Worker/动态 chunk 行为与 dev http 不一致，是 dev/打包差异（monaco 高亮、弹框异常）温床 |
| dev | 默认 dev server http；`SSHK_DEV_APP_PROTOCOL=1` 时也走 app:// | 同协议排查 dev/打包差异 |

- 实现：`apps/desktop/src/main/renderer-protocol.ts`——特权注册（app+localres 一次性，app ready 前）+ `protocol.handle('app')` 从 out/renderer 读静态文件（标准协议 standard/secure/corsEnabled，MIME 表，防穿越）；hash 路由无需 SPA fallback
- 诊断配套：主窗口 `console-message`（warn/error）落主进程日志，打包版现场问题不用开 DevTools 就能从日志看渲染层报错
