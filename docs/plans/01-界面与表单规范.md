## 一、表单布局规范（用户第 6 条，全局铁律）

### 1.1 布局原则

| 原则 | 内容 |
|---|---|
| **默认 2 列，宽松 3 列** | 同一配置分组内，短表单项（开关、下拉、短输入、数字）默认排 2 列；分组项少且都短时可用 3 列 |
| **特殊项独占整行** | 长文本 textarea、代码编辑器、路径选择（dir/file，带按钮）、表格/行编辑器、富文本、白名单多选大控件——独占整行 |
| **分组不打散（硬约束）** | 明显关联的一组配置（如「自动安装更新」开关+其说明、「分发白名单」选择+保存按钮、一对 host/port）**必须同组同区**，禁止为凑列数拆开；宁可整组独占一行 |
| **顺序即语义** | 开发表单时先提炼每项的归属分组与排列顺序（高频/主操作在前，低频/高级在后），再套列布局 |
| **响应式降级** | 窄窗口（<900px）自动降为单列，分组顺序不变 |

### 1.2 实现载体

| 项 | 方案 |
|---|---|
| 统一栅格 | `el-row/el-col` 或 CSS grid（`grid-template-columns: repeat(2, 1fr)` + `grid-column: span 2` 独占行），封装到 `@sshk/ui-kit` 的表单容器组件 `FormGrid`（`cols` / `full` 两类插槽） |
| 控件宽度 | 列内控件统一 `width: 100%`，由栅格控宽，禁止手写散乱宽度 |
| 独占行声明 | 字段清单（manifest configGroups）可选加 `full: true` 标记独占行——渲染层与向导/编辑器统一识别 |
| 存量改造 | AppSettingsDrawer 常规页、各工具 SettingsPage 表单、向导四步——逐个按新规范过一遍 |

## 二、hint 说明文案精简（用户第 2 条）

### 2.1 问题（截图实证）

设置抽屉「自动安装更新」「开发者模式」等项的说明文字 2-3 行长句，视觉噪音大、挤压布局。

### 2.2 规范

| 规则 | 内容 |
|---|---|
| **一句话原则** | hint 控制在**一行内（≤20 字）**，只说"这是什么/默认是什么"；长解释一律撤掉 |
| **问号弹出** | 需要保留的长解释 → 字段 label 后加问号图标（`QuestionFilled`），hover/点击弹出 `el-tooltip` 或 `el-popover` 展示完整说明 |
| **示例（截图两项）** | 「自动安装更新」hint → `默认关；开启后退出即自动安装`（长解释进 tooltip：「新版仅在后台下载，可在 系统与数据→更新 点立即安装」）；「开发者模式」hint → `仅打包版生效；源码 dev 恒开`（长解释进 tooltip） |
| **存量清理** | 全仓 grep `class="hint"` / `hint=` 逐条过一遍：一行内的保留、超行的精简、必要信息挪 tooltip |
| **文案口吻** | 直述、无"需要/请注意"类废话；关键词加粗或 `「」` |

## 五、控件尺寸与对齐规范（用户 2026-11-16 铁律，已全项目落地）

### 5.1 高度：一律 32px

| 规则 | 说明 |
|---|---|
| **全项目 32px 统一** | `theme.css` 把 Element Plus 的 small 档整体拉平到默认档（`--el-component-size-small: 32px` + 按钮/输入框/选择器/单选组/数字框的 padding、字号对齐默认档）。**页面级不要再写任何控件高度覆盖** |
| **size="small" 语义保留** | 密集表格等场景仍可写 `size="small"`（渲染与默认档同高，仅语义标记），**无需逐处删除**；新代码随便写，出来的高度必然一致 |
| **配套拉平** | tag（20→32px）、分页页码（24→32px）、复选/单选字号（12→14px）已配套对齐，同排不突兀 |
| **组内圆角归 EP** | 全局不覆盖 `border-radius`——单选按钮组/按钮组「首尾圆、中间段直角」由 EP 组规则按位置控制，全局覆盖会导致中间段出圆角 |
| **数字框加减钮** | 全局撑满输入框全高、左右对称同底色（EP 的 + 钮默认透明底，暗色主题下像缺失）；`el-input-number` small 档宽 150px |

### 5.2 label：多列表单 label-width="auto"

| 规则 | 说明 |
|---|---|
| **默认 auto** | EP 在同一 `el-form` 内取全部 label 的**最大宽度**统一对齐（短 label 右对齐到同一边缘），天然不换行，加字段免调宽度 |
| **禁用 auto 的场景** | `v-show` 切换的表单（MailEditor 步骤）、`el-tab-pane` 隐藏挂载的表单（ToolManifestDialog）——隐藏时测宽为 0 会让 label 塌陷，**保持固定宽度**（如 90px / 130px）且宽度须容下最长 label |
| **el-dialog / v-if 表单** | 可安全用 auto（懒挂载时可见） |

### 5.3 提示文案（tip）对齐

| 规则 | 说明 |
|---|---|
| **组件** | 提示一律用 `@sshk/ui-kit` 的 `FormHint`：默认上下放置（独占一行、与输入框精确左对齐）；`inline` 左右放置（留 12px 边距）；长解释进 `detail` 问号弹出 |
| **FormGrid 内的间距** | 由 `column-gap: 8px` 统一管——flex 列间隙只在同一行内生效：同线提示留 8px 边距，换行后的提示落在行首与输入框精确左对齐。**FormGrid 内的提示 span 不要再手写 margin-left**（FormHint inline 的 12px 已在栅格内中和） |

### 5.4 落地方式

- 全局规则都在 `apps/desktop/src/renderer/styles/theme.css`（尺寸/圆角/数字框/tag/分页）与 `packages/ui-kit/src/components/FormGrid.vue`（label 对齐/nowrap/column-gap）——**改规范只改这两处**，页面级零散覆盖视为违规
- 存量已核：8 处 el-dialog / v-if 表单 label-width 已转 auto（ContentManagePage、ProvidersPage、Brands/Fragments/Templates、FieldSchemaDesigner、UploadConfigPage）；MailEditor、ToolManifestDialog 按 5.2 例外保留固定宽度
