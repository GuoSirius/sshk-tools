# 02 · 工具创建与配置统一（向导 / 清单编辑器 / 卡片编辑 三合一治理）

- 状态：规划待确认
- 优先级：P0（批次 B1）
- 来源：用户 2026-11-16 第 4、5 条 + B-V3「功能流程界面需优化」+ B-V4「不完整、不美观」
- 现状组件：`CreateToolWizard.vue`（创建向导，dev-only）、`ToolManifestDialog.vue`（清单编辑器）、`AppSettingsDrawer.vue` 卡片内「编辑」表单（toolOverrides）

---

## 一、现状与问题（已核实代码）

| 界面 | 编辑对象 | 落点 | 问题 |
|---|---|---|---|
| 创建向导（分步 4 步 + JSON 预览） | 从零生成 manifest + 骨架文件 | `tools/<id>/` 全套落盘 | 与编辑器表单重复实现；defaults 是简化版（按类型自动生成）；界面细节待打磨 |
| 清单编辑器（配置按钮 → ToolManifestDialog） | 已有 `tool.manifest.json` | 写回 manifest 文件 + 目录重载 | 行编辑「总感觉不完整、不美观」；与向导两套表单逻辑 |
| 卡片「编辑」（就地展开） | `app.toolOverrides.<id>` 覆盖 | settings.json（不碰源） | 与前两者语义不同（源 vs 覆盖），但入口堆在一张卡片上，用户分不清 |

**用户核心诉求**：创建和配置理论上是同一件事（都是编辑 manifest），现在两套差异大（尤其默认值），应合并为一套，只是底部操作按钮不同。

## 二、合并方案

### 2.1 架构：一套表单区块组件 + 两种壳

```
packages/ui-kit 或 apps/desktop/renderer/components/tool-form/
├── BasicInfoSection.vue      # 基本信息：id(创建时必填/编辑时只读)、名称、描述、分类(autocomplete)、标签、可见性
├── MenusSection.vue          # 菜单与页面：菜单行编辑 + 派生页面文件名 + 形态2 configPages
├── CapabilitiesSection.vue   # 能力与权限：7 项宿主能力复选 + sandbox + ipcAllowlist 全表复选 + plugin.channels
├── ConfigSection.vue         # 配置项：configGroups 行编辑 + defaults 完整行编辑（重扫默认值 + 额外键保留）+ dependsOn/configDeps
└── JsonPreviewPane.vue       # 实时 JSON 预览（toManifest 只读）

壳 A：CreateToolWizard    = 空白起步 → 四区块分步/单页 + 骨架落盘（buildSkeletonFiles）→ 目录冲突拒绝
壳 B：ToolManifestDialog  = 载入现有 manifest → 四区块 + JSON 预览 tab + 底部动作（保存并校验 / 构建外部产物 / 打包应用 / 导出 .sshktool）
```

### 2.2 统一后的行为对齐（消除用户观察到的差异）

| 差异点 | 统一为 |
|---|---|
| defaults 编辑 | 统一用编辑器的**完整行编辑版**（按字段 key 派生行 + 重扫默认值 + 额外键保留）；向导第 4 步废黜简化版 |
| 分类输入 | 统一 autocomplete 下拉 + 手输（N17 已做，进共享组件） |
| 表单布局 | 统一按 01 文档新栅格规范（2 列 + 独占行标记） |
| JSON 预览 | 向导与编辑器共用同一预览窗格（预览即落盘原则不变：`buildSkeletonFiles` 单一事实源） |

### 2.3 「配置」vs「编辑」入口治理（Q4）

| 动作 | 说明 |
|---|---|
| 保留两者但改名辨义 | 「配置」→ 保留（源编辑，dev 专用）；「编辑」→ 改名「展示定制」或加图标+tooltip「覆盖卡片名称/图标等，不改工具源码」 |
| 卡片视觉分层 | 配置按钮加 `dev` 徽标；展示定制表单折叠收纳到二级（点击后展开），卡片默认态只留：开关 + 配置 + 展示定制 |
| 后续可再评估 | 把展示定制并入 ToolManifestDialog 的一个「展示覆盖」tab——**本轮先不做**（两者落点不同，混在一个弹窗反而 confusing；先做改名+分层，用一阵再看） |
