## 1. 现状（代码事实）

| 项 | 现状 |
|----|------|
| 引擎 | `FsTransferEngine`（main/fs.ts）：`tasks: Map` + `queued: string[]` + `runningByProfile`，同通道并发 远程 3 / 云 5；失败自动重试 1 次 |
| 状态机 | `queued → running → success / failed / canceled / conflict`；`cancel` 通过 `canceled: Set` + `sample()` 检查点生效（流式中最多等下一个进度采样） |
| 任务类型 | `upload / download / copy / delete / cross`（跨通道复制=源下载临时文件→目标写入）；目录删除入队带进度 |
| 控制 | IPC：`fsTransferStart / list / cancel / retry / clear`；UI 仅有「取消 / 覆盖 / 重试 / 清理已完结」 |
| 存储 | **纯内存**：任务与进度不持久化，应用重启队列丢失 |
| 分片 | **不支持**：`driver.write(path, Buffer \| Readable, onProgress)` 单流直传；OSS/S3 SDK multipart 未接入 |
| UI | `el-drawer direction=btt size=45%`，`close-on-click-modal=false`——打开后遮罩盖住整页，列表不可操作；状态条只有「传输队列（N 进行中）」入口按钮 |
| 推送 | `onEvent` 120ms 节流，全量任务形态下发，渲染层按 id 覆盖 |

## 2. 目标 / 非目标

**目标**

- G6 大文件下载分片 + 断点续传：按 local/SFTP/OSS/S3 的 Range 能力实现，落临时文件+校验元数据，完成后原子改名

- **位置/视图记忆**：`localStorage sshk.fs.transferPanel` 存 `{ x, y, expanded, tab, filter }`；默认展开状态按上次记忆，首次进入默认收起且摘要条有活动任务时高亮

- **行控制显隐**：`queued`→开始/停止；`running`→暂停/停止；`paused`→继续/停止；`conflict`→覆盖/停止；`failed/canceled`→重试/移除；`success`→移除。可续传任务（`resumable=true`）额外显示「继续」并标注「断点续传」
- **配色/确认**：开始/继续=primary，暂停/重试=warning，停止/移除/清理=danger；「全部停止」「清理已完结」「单条移除/停止」一律 `ElMessageBox.confirm`（禁遮罩/禁 ESC）
- **拖拽上传隔离**：面板内部 pointer/drag 事件 `stopPropagation`；window 级 drop 监听器对事件目标位于面板内时忽略，避免拖面板误触发上传

## 4. 引擎设计（G2-G3）

**状态扩展**：`FsTransferStatus` 增 `paused`。引擎增 `pausedAll: boolean`、`pausedIds: Set<string>`、`pauseRequestedIds: Set<string>`：

- `pause(ids)`：running 任务置 `pauseRequested`，UI 显示「暂停中…」；在下一个协作检查点（流 chunk / 分片 part / 目录项边界）抛 `__fs_paused__`，状态落 `paused`，**保留 `transferred` 与检查点**；queued 任务直接挂起（不出队）
- `resume(ids)`：清 paused 标记 → 重新入队；可续传任务走检查点续传，单流任务从头写并沿用既有冲突校验
- `stop(ids)`：等同现有 cancel，但**分片任务先 abort 服务端 uploadId 并清理本地检查点**（§5）；下载任务删临时文件与元数据
- `startAll()`：清 `pausedAll`，唤醒全部 paused/queued；`pauseAll()`：置 `pausedAll`，在途任务在检查点停下；`stopAll()` / `retryFailed()` / `clearFinished()` 按语义批量执行
- `pump()` 入口先看 `pausedAll`，暂停时不发车；`setStatus()` 维护 `runningByProfile` 计数，暂停同样释放并发额度
- **协作检查点统一走 `assertNotPaused(t)` / `assertNotCanceled(t)`**：`sample()` 内先暂停后取消；分片边界、下载 chunk 回调、目录项循环都要调用
- **IPC 收敛（不做兼容）**：删除 `fsTransferCancel / fsTransferRetry / fsTransferClear` 三个通道，新增单一 `fsTransferControl: 'fs:transfer:control'`（`action: 'start'|'pause'|'resume'|'stop'|'retry'|'remove'|'startAll'|'pauseAll'|'stopAll'|'retryFailed'|'clearFinished'`，`ids?: string[]`，`overwrite?: boolean`）；同步改 `packages/shared/src/ipc.ts`、main 注册、preload、`renderer/env.d.ts`、`scripts/check-ipc.mjs` / `check-preload.mjs`。`fsTransferStart / list / event / caps / capsSet` 保留
- **任务快照增字段**：`resumable?: boolean`（可续传）、`partsDone?/partsTotal?`（分片进度展示）、`persisted?: boolean`（从队列文件恢复）、`pausing?: boolean`（暂停中，UI 文案）
- `retry(ids, overwrite)`：失败/取消/暂停任务重新入队，可续传任务保留进度；`conflict + overwrite=true` 放行覆盖；`success` 任务重试按全新任务语义从头执行

## 5. 上传分片设计（G5）

**触发条件**：`kind=upload` + 文件大小 ≥ 阈值（默认 50MB，可配）+ 目标驱动支持 multipart（OSS/S3）。

**驱动契约**（`FsDriver` 可选扩展，不改现有写流程）：
```ts
multipart?: {
  create(): Promise<{ uploadId: string }>
  uploadPart(uploadId: string, partNumber: number, body: Buffer): Promise<{ etag: string }>
  listParts(uploadId: string): Promise<{ partNumber: number; size: number; etag: string }[]> // 内部翻页
  complete(uploadId: string, parts: { partNumber: number; etag: string }[]): Promise<void>
  abort(uploadId: string): Promise<void>
  listUploads?(): Promise<{ uploadId: string; key: string; initiatedAt?: number }[]> // 遗留分片清理
}
```
- 实现落点：`packages/upload-core/src/providers/fs-cloud.ts`（复用 `cloud-sdk.ts` 的 SDK 懒加载，不写字面量 `import()`）——OSS `multipartUpload*`，S3 `createMultipartUpload / uploadPart / completeMultipartUpload / abortMultipartUpload / listMultipartUploads`
- **配置**（「更多▾ → 传输设置…」）：`app.fs.multipart.enabled`（true）、`thresholdMb`（50，范围 1~1024）、`partSizeMb`（5，范围 5~100）、`partsConcurrency`（3，范围 1~8）。阈值/分片/并发全部实时生效、跨重启记忆；设置弹框遵循表单铁律（label `width:auto + nowrap`、必填红星、自动聚焦）
- **分片数上限**：OSS/S3 最多 10000 片；若 `size / partSizeMb > 10000`，自动上调 partSize 到满足上限的最小整数 MB，并在任务提示中说明
- **内存闸门**：同时开片的任务数上限 2；单片 Buffer 用完即释放；总并发 = 通道并发 × 分片并发，由全局闸门兜底
- **检查点**：`userData/fs-transfer/checkpoints/<taskId>.json`（uploadId、源文件绝对路径/size/mtimeMs、已完成 part 列表、目标 key）；每片完成即原子写（tmp+rename）
- **续传**：重启/重试时 `listParts` 与本地检查点按 `partNumber + size` 比对，只补缺片；源文件 size/mtime/路径任一不符 → 废弃检查点并 abort 旧 uploadId，重新开片
- **暂停/停止**：暂停=当前片写完不再发下一片（协作式）；停止=`abort(uploadId)` + 删检查点；崩溃遗留 uploadId 启动时**不自动清理**（避免误删别处同名对象的在途上传），面板/设置里显示「遗留分片 N 个」并提供手动清理入口（二次确认）
- **失败语义**：任一分片重试 1 次仍失败 → 任务 `failed`，**保留检查点**（点「重试」续传）；只有「停止」才清理

## 6. 下载分片与断点续传（G6，本期）

**触发条件**：`kind=download` + 文件大小 ≥ 阈值（复用 §5 的 `thresholdMb`）+ 驱动具备 Range 能力。

**驱动契约**（可选扩展）：
```ts
range?: {
  capabilities(): Promise<{ unit: 'bytes'; supportsRange: boolean }>
  statForResume(remotePath: string): Promise<{ size: number; fingerprint: string }> // 本地=mtimeMs；云=ETag/LastModified；远程=mtime+size
  readRange(remotePath: string, start: number, end: number): Promise<Buffer> // 或带 onProgress 的流式实现
}
```
- 落点：local（`createReadStream({start,end})`）、SFTP（`read` + offset）、OSS/S3（`cloud-sdk.ts` Range 请求）；不支持 Range 的通道直接回落单流，任务标 `resumable=false`
- **临时文件**：`<dest>.sshkpart` + 元数据 `<dest>.sshkpart.json`（源 fingerprint、总大小、已完成区间列表）；所有分片完成后校验总大小 → 原子 `rename` 到目标路径；同名冲突沿用既有覆盖确认流程
- **续传**：重启/重试时读取元数据，先 `statForResume` 比对 fingerprint；一致则只补缺区间，不一致则删临时文件从头下载；副本文件绝不在未完成时覆盖正式目标
- **暂停/停止**：暂停=当前 chunk 写完停下（协作式），保留临时文件与元数据；停止=删临时文件+元数据；失败保留临时文件供续传
- **进度**：`transferred` = 已完成字节数，分片视图复用 `partsDone/partsTotal` 展示

## 7. 持久化（G7）

- **存储**：`userData/fs-transfer/queue.json`（`version: 1`）+ §5/§6 的检查点/临时文件；写盘用 tmp+rename 原子落盘；状态变化防抖 300ms 写一次，应用退出前 flush
- **范围**：只持久化 `kind ∈ {upload, download}` 且状态为 `queued/running/paused/conflict/failed` 的任务；`success/canceled` 不持久化；copy/cross/delete 不写盘（**预留**）
- **恢复**：启动时读回任务，一律置为 `paused`（**不自动续跑**），`persisted=true`；面板显示「恢复任务 N 个」，用户点「全部开始」或单条「继续」才跑；running 任务的 `transferred` 与检查点引用一并恢复
- **通道失效**：profileId 不存在/被禁用时任务仍展示，标记失败原因「通道已不存在，请恢复配置后重试」，可移除或待配置恢复后重试
- **预留扩展（无需现在兼容）**：持久化层抽象为 `FsTransferStore { save(tasks), load(), remove(ids) }`，配 `canPersist(kind, status)` 判定（当前仅 upload/download）；schema 带 `version` 与判别式 `checkpoint: { type: 'multipart'|'range'|'none', ... }`。后期接入其它类型只需扩展判定与 checkpoint 分支，不用迁移现有数据（用户明确不做兼容）
