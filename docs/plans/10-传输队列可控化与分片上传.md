## 1. 现状（代码事实）

| 项 | 现状 |
|----|------|
| 引擎 | `FsTransferEngine`（main/fs.ts）：`tasks: Map` + `queued: string[]` + `runningByProfile`，同通道并发 远程 3 / 云 5；失败自动重试 1 次 |
| 状态机 | `queued → running → success / failed / canceled / conflict`；`cancel` 通过 `canceled: Set` + `sample()` 检查点生效（分片/流式写入中不会立即中断，最多等到下一个进度采样） |
| 任务类型 | `upload / download / copy / delete / cross`（跨通道复制=源下载临时文件→目标写入）；目录删除入队带进度 |
| 控制 | IPC：`transferStart / list / cancel / retry / clear`；UI 仅有「取消 / 覆盖 / 重试 / 清理已完结」 |
| 存储 | **纯内存**：任务与进度不持久化，应用重启队列丢失（传输中断不可恢复） |
| 分片 | **不支持**：`driver.write(path, Buffer \| Readable, onProgress)` 单流直传；OSS/S3 SDK 的 multipart 能力未接入 |
| UI | `el-drawer direction=btt size=45%`，`close-on-click-modal=false`——打开后遮罩盖住整页，列表不可操作；状态条只有「传输队列（N 进行中）」入口按钮 |
| 推送 | `onEvent` 120ms 节流，全量任务形态下发，渲染层按 id 覆盖 |

## 2. 目标 / 非目标

**目标**
- G1 内嵌区块：传输面板放在列表下方（状态条上方），可展开/折叠；**展开时列表照常滚动、选中、右键、翻目录**，不遮罩、不锁页面
- G2 整体控制：全部开始 / 全部暂停 / 全部停止 / 失败全部重试 / 清理已完结（对齐 oss-browser 的 ▶ ⏸ 🗑 语义）
- G3 单条控制：暂停 / 继续 / 停止 / 重试 / 覆盖 / 移除（按状态显隐，类似截图每行末尾 ×）
- G4 上传/下载分栏 + 名称搜索过滤（对齐截图「上传 4/4」「下载 0/0」标签页）
- G5 大文件分片上传：阈值可配、分片可配、断点续传（重启后继续）、取消时可清理服务端碎片
- G6 所有传输类型纳入同一面板（上传 / 下载 / 复制 / 跨通道 / 删除），控制按类型能力开放（如「暂停」对瞬时 cp 任务可禁用）

**非目标（本期不做）**
- 下载分片（先复用现有 stream 下载；下载断点续传列二期）
- 全局流量限速 / 带宽调度（留接口，不实现）
- 云厂商全覆盖：分片只在 **阿里云 OSS / AWS S3**（当前仅这两家可写）落地，其余保持单流

## 4. 引擎设计（G2-G3）

**状态扩展**：`FsTransferStatus` 增 `paused`。引擎增 `pausedAll: boolean` 与 `pausedIds: Set<string>`：
- `pause(ids)`：running 任务置 `paused`，**协作式中断**——流/分片边界检查点抛 `__fs_paused__`，保留 `transferred` 与分片检查点；queued 任务直接挂起（不出队）
- `resume(ids)`：清 paused 标记 → 重新入队（分片任务走续传，单流任务从头写并做覆盖校验）
- `stop(ids)`：等同现有 cancel，但**分片任务先 abort 服务端 uploadId 并清理本地检查点**（见 §5）
- `startAll()`：清 `pausedAll`，唤醒全部 paused/queued；`pauseAll()`：置 `pausedAll`，running 任务在下一个采样点暂停
- `pump()` 入口先看 `pausedAll`，暂停时不发车（已在途任务靠中断点停下）
- 所有控制经 IPC 新通道 `fs:transferControl`（`action: 'start'|'pause'|'resume'|'stop'|'retry'|'remove'|'startAll'|'pauseAll'|'stopAll'|'retryFailed'|'clearFinished'`, `ids?: string[]`）——一个通道收敛，避免通道爆炸；`check-ipc.mjs` 同步白名单
- 任务快照增 `resumable?: boolean`（是否具备断点续传能力），UI 据此显示「继续」按钮
- **兼容性**：`transferCancel/Retry/Clear` 旧通道保留为 `transferControl` 的薄封装（不破坏已有调用与验收脚本）

## 5. 分片上传设计（G5）

**触发条件**：`kind=upload` + 文件大小 ≥ 阈值（默认 50MB，可配）+ 目标驱动支持 multipart。
**驱动契约**（`FsDriver` 可选扩展，不改现有写流程）：
```ts
multipart?: {
  create(): Promise<{ uploadId: string }>
  uploadPart(uploadId: string, partNumber: number, body: Buffer): Promise<{ etag: string }>
  listParts(uploadId: string): Promise<{ partNumber: number; size: number; etag: string }[]>
  complete(uploadId: string, parts: { partNumber: number; etag: string }[]): Promise<void>
  abort(uploadId: string): Promise<void>
}
```
- 实现落点：`packages/upload-core/src/providers/fs-cloud.ts`（复用 `cloud-sdk.ts` 的 SDK 懒加载，不写字面量 `import()`）——OSS `multipartUpload*`，S3 `createMultipartUpload/uploadPart/completeMultipartUpload/abortMultipartUpload`
- 分片大小默认 5MB（OSS/S3 最小 5MB，末片不限），分片并发 3；**总并发上限 = 通道并发 × 分片并发**，须加全局闸门防止 N 个大文件同时开片打满内存（Buffer 按片申请，单片 5MB）
- 检查点：`userData/fs-transfer/checkpoints/<taskId>.json`（uploadId、源路径哈希/大小/mtime、已完成 part 列表）；每次 part 完成即原子写盘
- 续传：任务重启/重试时 `listParts` 与本地检查点比对（partNumber+size），只补缺片；源文件内容变更（size/mtime 不符）→ 废弃检查点重新开片
- 取消/停止：`abort(uploadId)` + 删检查点；应用崩溃遗留的 uploadId 在下次启动时**不自动清理**（避免误删用户正在别处上传的同名对象），在面板显示「遗留分片 N 个」并提供手动清理入口
- 配置键（更多▾→传输设置…）：`app.fs.multipart.enabled`（默认 true）、`thresholdMb`（50）、`partSizeMb`（5，范围 5~100）、`partsConcurrency`（3，范围 1~8）
- 失败语义：任一分片重试 1 次仍失败 → 任务 `failed`，**保留检查点**（点「重试」续传）；只有「停止」才清理

## 6. 持久化（待拍板）

现状队列纯内存。分片断点续传若只在同一进程内有效，价值有限。建议（**待拍板**）：
- 任务元数据 + 检查点一起持久化到 `userData/fs-transfer/queue.json`（只存可恢复的 upload/download，不存 copy/cross/delete）
- 启动时恢复为 `paused` 状态（**不自动续传**，用户点「全部开始」才跑——避免打开应用就偷偷上传）
- 与「暂停」语义天然统一；面板标签显示「恢复任务 N 个」

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 分片并发 × 任务并发打满内存 | 全局闸门限制同时开片任务数（建议 2），单片 Buffer 用完即释放 |
| 暂停不即时（流阻塞） | 协作式中断：分片边界/流 chunk 回调检查，UI 状态显示「暂停中…」直到真正 paused |
| 服务端碎片泄漏 | abort 幂等；检查点与 uploadId 绑定；面板提供手动清理入口 |
| 检查点与源文件不一致 | size+mtime 双校验，变更即作废重传 |
| 面板挤压列表导致小屏不可用 | 展开高度 200px 固定且可折叠；折叠态记忆；最小列表高度保护 |
| 与新 subgrid 列表互相影响 | 面板在 `.fs-list` 之外，独立 flex 项，不动列轨道 |
