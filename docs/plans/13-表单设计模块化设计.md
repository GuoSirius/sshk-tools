  icon?: string

## 九、遗留问题排查与修复方案（2026-11-23 排查，修复待敲板）

### 9.1 富文本粘贴图片：选位置确认后「没反应」不插入（bug）

**根因（wangEditor 5.1.23 dist 实锤，两层叠加）：**

1. **主因——`insertFn` 内置静默守卫**：粘贴路径走的 wangEditor `insertImageNode`（`@wangeditor/editor/dist/index.js` 中 `na` 函数）末尾是
   `oa(t) ? [2] : Transforms.insertNodes(...)`，其中守卫 `oa`（`isInsertImageMenuDisabled`）在以下情况**静默丢弃、无任何报错**：
   - 编辑器 `selection == null`（弹框交互把焦点移走后选区状态不可控，`restoreSelection()` 拿不到快照时同样无效）；
   - 光标非折叠（选中有内容时粘贴）；
   - 光标位于 header / blockquote / list-item / link / pre / code / void 节点内（标题行、引用、列表里粘贴必中）。
   对照：工具栏图片库路径 `onLibraryConfirm` 用 `editor.focus() + editor.dangerouslyInsertHtml('<img …>')`，不经过该守卫，实测可用。
2. **次因——确认回调无容错导致持续失效**：`onUploadTargetConfirm` 的 `for…await` 循环无 try/catch——任一张图上传/插入抛错 → 整批中断 + `batchTarget` 未复位 → 后续每次粘贴复用坏批次（不再弹框、直接走已失败的插入路径），表现为「从某次起粘贴一直没反应」。

**修复方案（改 `packages/rich-text/src/components/RichTextEditor.vue`）：**

| # | 改动 | 说明 |
|---|---|---|
| 1 | `uploadPastedImage` 弃用 wangEditor `insertFn`，改直插通道 | 有 editorRef 时：`editor.restoreSelection()` + `editor.insertNode({type:'image', src, style:{}, children:[{text:''}]})`（与工具栏同源、绕开 `oa` 守卫）；editorRef 不可用时才回落 `insertFn` |
| 2 | `onUploadTargetConfirm` 逐项 try/catch | 单张失败 `ElMessage.error` 提示并继续下一张；`batchTarget` 在 `finally` 复位，杜绝坏批次粘滞 |
| 3 | 上传失败回退 dataURL 时给 warning toast | 现状静默回退，用户无从感知（排查可见性） |
| 4 | 验证 | 光标分别在 正文段落 / 标题行 / 列表 / 引用 / 已选文字 时粘贴→确认，全部插入；断网/密钥失效时 toast 可见；多张连贴一批次行为不变 |
