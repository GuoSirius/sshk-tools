## 一、需求背景（用户 2026-11-23）

**任务一 · FilePicker/UploadTarget 收口**：两组件已落地，核实覆盖面；「整个应用内记住上次位置」要求全局统一（FilePicker 与 UploadTarget 均如此）；确认覆盖后彻底清除其他模块/工具中残留的上传配置。

**任务二 · 「表单设计」应用内置模块**：
1. 模块名「表单设计」，一级菜单 **表单管理、控件管理**（按顺序），默认进入表单管理。
2. 表单管理 = 列表 + 正常增删改查 + 批量操作，可预览设计好的表单。
3. 控件管理 = 除系统内置基础控件与复合控件外，可创建**自定义复合控件**；且可基于基础控件、系统内置复合控件、已有自定义复合控件再组合出新复合控件（递归扩展）。
4. 模块完成并测试通过后，EDM 示例数据的表单设计部分使用这些控件，并可**下拉选择已创建的表单**、在此基础上增减修改。

## 五、阶段 C：控件管理 + 复合控件

**数据模型**

```ts
// packages/repository/src/entities.ts
interface ControlDoc extends BaseEntity {
  key: string          // 引用键，KEY_RE 约束、跨集合唯一
  label: string
  icon?: string
  description?: string
  version: number      // 每次编辑 +1
  builtin: boolean     // 系统播种，只读
  root: unknown        // 容器型 FieldDef（type ∈ list/repeater/table），itemFields 可含 controlKey 引用节点
}
```

- BACKUP_COLLECTIONS 加 `'formControls'`、ID_PREFIX `formControls: 'ctl'`；shared 加 ControlRecord/ControlSaveInput 与 `formControl:*` 通道。
- **design-time 引用 + runtime 展开**：表单/控件存储树中复合控件以 `{key,label,type:'repeater',controlKey}` 占位；`packages/form-schema/src/expand.ts` 纯函数：
  - `expandFields(fields, controlMap)`：递归把 controlKey 节点替换为控件 root 深拷贝；**渲染、校验、导出前一律先展开**。
  - `collectControlKeys(fields)`：收集引用键（存 FormDoc.controlsUsed）。
  - `compositeDepth(root, controlMap)`：展开深度校验，**上限 3 层**（对齐 EDM canNest 先例）。
- **循环引用防护（结构上）**：控件保存时对引用树做深度校验（≤3），引用选择器只列已保存控件、剔除会超深的候选——无法成环。
- **删除拦截**：`controlRemove` 前反查 forms.controlsUsed，命中 `AppError('被表单 X/Y 引用，先解除引用','validation')`；builtin 禁删禁改。
- **播种**：内置复合控件常量放 `builtin-controls.ts`（2-3 个示例，如「联系人组」）；主进程 form 模块启动 `ensureSeedControls(repo)` 按 key 幂等补插（`builtin:true`）。
- **UI**：新 `forms/pages/ControlsManagePage.vue`（列表含 builtin/引用计数列；编辑 = 元信息 + FieldSchemaDesigner，插入时弹复合控件选择器）；FormsManagePage 设计器加「插入复合控件」入口；设计器支持 controlKey 节点显示与解除引用。

验收：expand/深度/环检测单测；控件 CRUD + 引用删除拦截走查；表单引用控件后改控件 → 预览即时反映。
