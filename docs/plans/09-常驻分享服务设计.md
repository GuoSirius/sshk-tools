# 09 · 常驻分享服务（ShareHub）设计

> 状态：**草案，待用户评审后定稿**（2026-11-17 用户提出设想：随应用启动的常驻服务 + 工具按需注册路由，本文展开为可实施方案）。
> 关联：`packages/share-core`（现有分享内核）、badge-studio 海报分享（C-T1）、edm-studio 产物分享、`docs/plans/08-文件管理系统.md`（下载/外链）。

---

## 一、背景与现状

### 1.1 现有实现
`@sshk/share-core` 提供单实例 `ShareServer`：
- 一个 root 目录 + 一个 token + 一个 TTL（默认 72h），HTTP 静态只读服务；
- 状态文件持久化（`<userData>/edm-share-state.json` 等），应用重启后 `resume()` 恢复未过期会话；
- 「重新生成」换 token，旧链接立即失效；`stop()` 立即下线。

### 1.2 现有使用方（两个，且互相独立）
| 使用方 | root | 端口 | 状态文件 |
|---|---|---|---|
| badge-studio 海报分享 | `<output>/海报产物` | 独立 | `badge-share-state.json` |
| edm-studio 产物分享 | `<output>/outputs` | 独立 | `edm-share-state.json` |

### 1.3 现状痛点（用户设想针对的问题）
1. **多实例多端口**：每个工具一个 ShareServer，占多个端口，防火墙/局域网访问要放行多次；
2. **没有统一生命周期**：服务随「第一次分享」被动拉起，没有「随应用启动」的显式开关，也没有统一的启动/重启/停止操作与状态查看；
3. **扩展性差**：第三个工具要分享，又要复制一套 server/状态文件/IPC 四件套；
4. **token 语义单薄**：一 token 绑一整棵目录树，无法按「分享一个文件 / 一个目录 / 一个入口页」精细授权，也没有访问日志、密码保护等。

---

## 二、目标与非目标

### 目标
1. **常驻单例**：应用内唯一的 HTTP 分享服务 `ShareHub`（单端口）；
2. **生命周期可控**：随应用启动（可配置 `app.shareHub.autoStart`，默认开）；设置页提供 启动 / 重启 / 停止 / 状态查看；
3. **多租户路由**：工具按需注册「分享路由」——每个分享独立 token、独立 TTL、独立 root/path，可撤销；
4. **工具接入成本趋近于零**：主进程一套注册 API + 渲染层一层桥接，工具不再自持 server；
5. **平滑迁移**：badge / edm 现有分享行为（链接形态、72h、跨重启恢复）保持不变。

### 非目标（本期不做）
- 公网穿透 / 域名映射（可作三期探索）；
- HTTPS / 域名证书；
- 大规模并发（局域网只读场景，Node http 裸服务足够）。

## 三、总体架构

### 3.1 结构

```
┌─ 渲染层（工具 A/B/C…）────────────────────────────────┐
│  window.api.shareHub.create/list/revoke/status        │
├─ preload 桥（IPC 白名单）─────────────────────────────┤
│  shareHub:create / shareHub:list / shareHub:revoke    │
│  shareHub:status / shareHub:restart                   │
├─ 主进程 ──────────────────────────────────────────────┤
│  ShareHub（常驻单例, share-core 重写扩展）             │
│   ├─ http server（单端口, 状态: running/stopped）      │
│   ├─ 路由表 Map<token, ShareRoute>                    │
│   │    ShareRoute { toolId, root, entry, ttl,         │
│   │            expiresAt, label, createdAt }          │
│   ├─ TTL 过期清理（定时器 + 访问时惰性校验）           │
│   ├─ 状态持久化 hub-state.json（重启 resume）         │
│   └─ 访问日志环形缓冲（诊断页可看）                    │
└───────────────────────────────────────────────────────┘
```

### 3.2 生命周期
| 时机 | 行为 |
|---|---|
| 应用启动 | 读 `app.shareHub.autoStart`（默认 `true`）→ `hub.start()`；读 `hub-state.json` 恢复未过期路由 |
| 用户点「重启服务」 | 换端口重试 + 保留全部路由与 token（token 属于路由，不属于进程） |
| 用户点「停止服务」 | 关端口、路由表保留（再次启动即恢复）；也提供「停止并清空」 |
| 退出应用 | 清理状态文件中已过期路由，未过期保留供 resume |
| 端口被占 | 默认 `app.shareHub.port = 0`（系统分配）；配置固定端口被占时告警并回落随机端口 |

### 3.3 路由与 URL 形态
```
http://<局域网IP>:<port>/<token>/              ← 入口（entry 指定默认文件或目录列表页）
http://<局域网IP>:<port>/<token>/<relPath>     ← 相对 root 的资源
```
- **token 与路由绑定**：一次 `create()` 生成一个 token（12B base64url），一个服务可同时挂 N 个 token；
- **TTL 到期**：路由摘除，链接 404；`expiresAt` 随创建返回，UI 显示剩余时间；
- **防目录穿越**：relPath 规范化后必须落在 root 内（现有 ShareServer 已有此逻辑，平移）；
- **可选密码**（三期）：`ShareRoute.password`，入口页要求 ?key= 校验。

### 3.4 注册 API（主进程，share-core 内）
```ts
interface ShareRouteInput {
  toolId: string                    // 归属工具（'badge-studio' | 'edm-studio' | …）
  label: string                     // 展示名（「海报：产品A」）
  root: string                      // 允许被访问的目录（绝对路径）
  entry?: string                    // 入口相对路径（缺省=目录列表页）
  ttlHours?: number                 // 默认 72
}
interface ShareRouteTicket {
  id: string; token: string
  urls: string[]                    // 各网卡局域网地址
  expiresAt: number
}
class ShareHub {
  start(port?: number): Promise<{ port: number }>
  stop(): Promise<void>
  restart(): Promise<{ port: number }>
  status(): { running: boolean; port: number; routes: ShareRouteInfo[] }
  create(input: ShareRouteInput): Promise<ShareRouteTicket>
  revoke(idOrToken: string): Promise<boolean>          // 单路由撤销
  revokeByTool(toolId: string): Promise<number>        // 工具批量撤销
  renew(idOrToken: string, ttlHours: number): Promise<ShareRouteTicket>
}
```

### 3.5 渲染层桥（工具统一入口）
```ts
window.api.shareHub = {
  create(input): Promise<ShareRouteTicket>
  list(): Promise<ShareRouteInfo[]>        // 本工具 + 全局（status 内聚合）
  revoke(id): Promise<boolean>
  status(): Promise<HubStatus>
}
```
工具典型用法（以海报分享为例）：
```ts
const ticket = await window.api.shareHub.create({
  toolId: 'badge-studio', label: `海报：${poster.name}`,
  root: posterOutputDir, entry: 'index.html', ttlHours: 72,
})
await window.api.os.clipboardWrite(ticket.urls[0])
```

## 四、工具场景全景（注册 API 能覆盖的）

| 场景 | root | entry | 说明 |
|---|---|---|---|
| badge 海报分享 | 海报产物目录 | `index.html` | 现有行为 1:1 迁移 |
| EDM 邮件产物预览 | `outputs` | 指定邮件 html | 现有行为 1:1 迁移 |
| 单文件外链 | 文件所在目录 | 该文件名 | 文件管理系统「复制链接」的升级版（有 TTL、可撤销） |
| 目录交付 | 任意交付目录 | 列表页 | 给同事/客户交付一批文件 |
| 表格/文档快照 | 导出目录 | 导出文件 | sheet/doc 导出的临时分享 |
| （三期）回调入口 | —— | —— | 非静态：注册自定义 handler（如 webhook 接收），接口预留 `handler?: (req,res)=>void` |

> 三期的 `handler` 注册让 ShareHub 也能承接动态路由（工具自处理请求），但一期不实现，仅在接口上留位。

## 五、迁移与兼容

1. `ShareServer` 类保留但标记 deprecated，ShareHub 内部复用其静态文件服务内核（MIME/防穿越/Range）；
2. badge / edm 删除自持实例与状态文件逻辑，改调 ShareHub；旧状态文件一次性读取迁移进 hub-state.json（未过期的照搬）；
3. **已发出的旧链接**：迁移后端口/token 若变化会失效——迁移版本发布说明中注明「旧分享链接需重新生成」；若要无缝，ShareHub 启动时按旧端口监听并把旧 token 注册为等价路由（一期评估工作量后决定，默认从简）；
4. IPC：`badge:share:*` / `share:start|stop|status` 通道保留签名，内部转发 ShareHub（工具渲染层零改动）。

## 七、风险与待定项（请用户确认）

| # | 事项 | 倾向方案 |
|---|---|---|
| 1 | 旧链接兼容 | 从简：迁移后旧链接需重新生成（版本说明注明） |
| 2 | 端口策略 | 默认随机端口（0）+ 设置页可固定；固定端口冲突时回落并告警 |
| 3 | autoStart 默认值 | 默认开（用户设想即「随应用启动」）；可在设置关 |
| 4 | 路由上限 | 单工具 ≤ 20 条、全局 ≤ 100 条，防表膨胀（超出提示先撤销） |
| 5 | 「停止服务」语义 | 停止=关端口保留路由；另设「停止并清空全部路由」按钮 |
| 6 | 三期 handler 回调 | 一期只在接口留位，不实现 |

## 八、一期验收清单（拟）
1. 冷启动应用（autoStart=开）→ 设置页显示「分享服务运行中 · 端口 xxxx」；
2. autoStart=关 → 不监听端口，卡显示「已停止」；
3. badge 分享海报 → 链接形态与现版一致，手机/同事局域网可访问；
4. 72h TTL 到期（可临时改 0.01h 验证）→ 链接 404，路由列表自动摘除；
5. 重启应用 → 未过期链接继续可用（resume）；
6. 「重新生成」→ 新 token 生效、旧链接失效；
7. 停止服务 → 所有链接立即不可访问；重启服务 → 未过期路由恢复；
8. 撤销单条路由 → 对应链接失效，其它路由不受影响；
9. relPath 带 `..` 穿越 → 403/404，不泄露 root 外文件；
10. 端口被其它程序占用 → 自动换端口成功并提示。
