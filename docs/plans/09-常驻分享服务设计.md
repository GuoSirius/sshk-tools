# 09 · 常驻分享服务（ShareHub）设计

> 状态：**v2 定稿 + 3 个待确认点已全部拍板（2026-11-17），待用户最终通知开工**。

## 一、背景与现状

### 1.1 现有实现（将被完全替换，不做兼容）
`@sshk/share-core` 的单实例 `ShareServer`：一 root + 一 token + 一 TTL 的静态只读服务；badge-studio（海报产物）与 edm-studio（outputs）各自持有独立实例/端口/状态文件。

### 1.2 现状痛点
1. 多实例多端口，防火墙要放行多次；
2. 无统一生命周期（无「随应用启动」开关、无启动/重启/停止操作与状态查看）；
3. 第三个工具要分享需复制整套 server/状态/IPC 四件套；
4. token 语义单薄：一 token 绑一整棵目录树，无精细授权、无访问日志、无密码保护。

### 1.3 处置原则（用户拍板：干净彻底）
- `ShareServer` 类**直接删除**，不做 deprecated 过渡；
- badge / edm 的自持实例、状态文件、旧 IPC 通道**全部拆除**，改接 ShareHub 新 API；
- 旧状态文件（`badge-share-state.json` / `edm-share-state.json`）启动时**检测到即删除**，不读取不迁移；
- **旧分享链接全部失效**（发布说明注明「旧链接需重新分享」）。

## 二、目标与非目标

### 目标
1. **常驻单例**：应用内唯一 HTTP 分享服务 `ShareHub`（单端口，0.0.0.0 监听）；
2. **生命周期可控**：随应用启动（`app.shareHub.autoStart`，默认开）；独立设置 tab 提供启动 / 重启 / 停止（保留路由）/ 停止并清空 / 状态查看；
3. **多租户路由**：工具按需注册分享路由——独立 token、独立 TTL、独立 root/entry，可撤销可续期；
4. **工具接入成本趋近于零**：主进程一套注册 API + 渲染层统一桥接 + ui-kit 统一分享对话框；
5. **IP 可控**（新）：自动优选内网 IP，用户可在设置中改选或手输，选定后分享链接优先使用。

### 非目标
- 公网穿透 / 域名映射（本期不做，接口不预留）；
- HTTPS / 证书；
- 大规模并发（局域网只读场景，Node http 裸服务足够）。

## 三、总体架构

```
┌─ 渲染层（工具 A/B/C…）────────────────────────────────────┐
│  统一分享对话框 ShareDialog（ui-kit）：创建/列表/撤销/续期   │
├─ preload 桥（IPC 白名单）─────────────────────────────────┤
│  shareHub:create / shareHub:list / shareHub:revoke        │
│  shareHub:renew / shareHub:status / shareHub:control      │
├─ 主进程 ──────────────────────────────────────────────────┤
│  ShareHub（share-core 从零重写）                           │
│   ├─ http server（0.0.0.0:port，状态 running/stopped）     │
│   ├─ 路由表 Map<token, ShareRoute>                        │
│   │    { id, toolId, label, root, entry, ttl, expiresAt,  │
│   │      createdAt }                                      │
│   ├─ TTL 清理：定时器（60s）+ 命中时惰性校验双保险         │
│   ├─ 状态持久化 hub-state.json（重启 resume 未过期路由）   │
│   ├─ 访问日志环形缓冲（最近 500 条，诊断 tab 可看）        │
│   └─ IP 服务：枚举本机 IPv4 + 优选 + 读用户配置            │
└───────────────────────────────────────────────────────────┘
```

### 3.1 生命周期
| 时机 | 行为 |
|---|---|
| 应用启动 | 读 `app.shareHub.autoStart`（默认 `true`）→ `hub.start()`；读 `hub-state.json` 恢复未过期路由（已过期的不恢复并从文件剔除） |
| 用户「重启服务」 | 重启端口监听，**保留全部路由与 token**（token 属于路由不属于进程） |
| 用户「停止服务」 | 关端口，路由表保留（再启动即恢复） |
| 用户「停止并清空」 | 关端口 + 路由表清空 + 状态文件删除（所有链接永久失效） |
| 退出应用 | 状态文件只保留未过期路由 |
| 端口策略 | `app.shareHub.port` 默认 `0`（系统随机分配）；设了固定端口被占 → 回落随机端口并 ElMessage 告警 |
| 系统睡眠恢复 | 监听 `powerMonitor.resume` → 自动 restart（保留路由） |

### 3.2 路由与 URL 形态
```
http://<展示IP>:<port>/<token>/              ← 入口（entry 指定默认文件或目录列表页）
http://<展示IP>:<port>/<token>/<relPath>     ← 相对 root 的资源
```
- token 与路由绑定：一次 `create()` 生成一个 token（12B base64url），单服务可挂任意数量路由（**不设上限**，路由表内存态、状态文件落盘）；
- TTL 到期：路由摘除、链接 404；创建返回 `expiresAt`，UI 显示剩余时间；
- 防目录穿越：relPath 规范化后必须落在 root 内；
- MIME / 目录列表页 / Range 请求（音视频拖进度条）在静态内核实现。

### 3.3 主进程 API（share-core 内，`ShareHub` 类）
```ts
interface ShareRouteInput {
  toolId: string        // 归属工具（'badge-studio' | 'edm-studio' | …）
  label: string         // 展示名（「海报：产品A」）
  root: string          // 允许被访问的目录（绝对路径，主进程校验存在）
  entry?: string        // 入口相对路径（缺省 = 目录列表页）
  ttlHours?: number     // 默认 72；0.01 可用于测试
  password?: string     // 可选访问口令（轻量 key 校验，见 §D）
}
interface ShareRouteTicket {
  id: string; token: string
  urls: string[]        // 基于「展示 IP」生成（展示 IP 排第一，其余有效候选兜底）
  expiresAt: number
}
class ShareHub {
  start(port?: number): Promise<{ port: number }>
  stop(): Promise<void>                    // 停止，保留路由
  clear(): Promise<void>                   // 停止并清空全部路由
  restart(): Promise<{ port: number }>
  status(): HubStatus                      // { running, port, routes[], displayIp }
  create(input: ShareRouteInput): Promise<ShareRouteTicket>
  revoke(idOrToken: string): Promise<boolean>
  renew(idOrToken: string, ttlHours: number): Promise<ShareRouteTicket>
  /** IP 枚举与虚拟标记（见 §四），供设置 tab 展示 */
  listIps(): { ip: string; nic: string; virtual: boolean }[]
}
```

### 3.4 IPC 与渲染层桥
```ts
window.api.shareHub = {
  create(input): Promise<ShareRouteTicket>
  list(): Promise<ShareRouteInfo[]>       // 按调用方 toolId 过滤展示
  revoke(id): Promise<boolean>            // 仅能撤销自己工具的路由
  renew(id, ttlHours): Promise<ShareRouteTicket>
  status(): Promise<HubStatus>
}
// 生命周期控制（启动/重启/停止/清空）仅宿主「分享服务」tab 可用：
window.api.shareHubControl = { start, restart, stop, clear }
```
- IPC 白名单新增 6 条：`shareHub:create / list / revoke / renew / status / control`；
- **权限**：`create/revoke/renew` 按 toolId 记账——工具只能撤销/续期**自己创建**的路由；宿主可管理全部。

### 3.5 ui-kit 统一分享对话框（工具接入零成本）
`ShareDialog`：入参 `{ toolId, label, defaultRoot, defaultEntry, defaultTtlHours }`，内部完成 创建 → 展示链接（多 IP 可切换）→ 复制 → 剩余时间倒计时 → 撤销/续期。工具页面只需一行 `<ShareDialog v-model="open" ... />`。

## 四、IP 策略（用户拍板第 7 条，细化设计）

### 4.1 总原则
- **监听一律 `0.0.0.0`**：所有网卡上的 IP 天然都可访问本服务；
- **「展示 IP」只影响分享链接里写哪个地址**——多内网 IP 时默认选对、可改、可手输。

### 4.2 IP 枚举
`os.networkInterfaces()` 枚举全部 IPv4 非内部地址，标注 NIC 名称与 virtual 标记：

| 判定 | 规则 |
|---|---|
| 排除（virtual=true） | NIC 名含 `vEthernet / VMware / VirtualBox / Loopback / Docker / WSL / TAP / TUN / Tailscale / 蓝牙` |
| 排除（无效） | APIPA `169.254.*`、`127.*` |
| 有效候选 | 其余 IPv4，按 NIC 名（以太网/WLAN 优先）与地址段排序 |

### 4.3 自动优选规则（用户未手动选择时）
按优先级取第一个命中：
1. **配置过的展示 IP**（`app.shareHub.preferredIp`）仍在本机网卡上 → 永远最优先（用户选过就尊重）；
2. `10.*`（企业/自定义内网，用户本机 10.10.101.241 属此类）；
3. `192.168.*`（家庭/办公路由网段）；
4. `172.16–172.31.*`（最可能被 Docker/虚拟网占用，最后）；
5. 都没有 → `127.0.0.1`（本机自测）。

> 说明：把 `10.*` 放在 `192.168.*` 前，是因为 192.168 段常见于虚拟网卡兜底地址，而 10.x 出现时几乎总是真实业务内网——与用户「10.10.101.241 优先」的实例一致。

### 4.4 用户可控（「分享服务」tab 内）
- **「分享地址 IP」控件**：
  - 下拉列出全部检测到的 IP（每项显示 `IP · NIC名 · (虚拟)`，virtual 置灰但可选）；
  - 首项「自动（推荐）」= 按 §4.3 优选，选中时每次生成链接实时重算（插拔网线/换网自动跟随）；
  - 支持手输任意 IPv4（格式校验；输入检测列表之外的地址给出黄色提示「该 IP 未在当前网卡上检测到，链接可能无法访问」但不阻止保存）；
- **持久化**：`app.shareHub.preferredIp`（`''` = 自动）；变更立即生效，已发链接**不追溯改写**（新分享用新 IP）；
- **多 IP 兜底**：`create()` 返回 `urls[]` 含全部有效候选 IP 的链接（展示 IP 排第一），复制时可切换。
