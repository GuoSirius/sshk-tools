## 二、数据层设计（NeDB ✅ 可行）

项目已有 NeDB 数据层 `@sshk/repository`（@seald-io/nedb，纯 JS 免跨架构 rebuild，D11），新增集合零新增依赖：

| 项 | 设计 |
|---|---|
| 集合名 | `contents`（BACKUP_COLLECTIONS 成员，文章是用户数据应随备份 zip 导出；`backup/data/` 映射与 `@sshk/backup` 同步） |
| ID 前缀 | `cnt`（entityId 规约） |
| 文档模型 | `ContentDoc extends BaseEntity { name: string（必填）; html: string（toStoredHtml 存储态）; summary?: string; tags?: string[]; status?: 'draft' }` |
| 软删除 | 沿用 repository 惯例 `archived:true`；硬删仅二次确认后触发（危险操作铁律） |
| 大小 | wangEditor HTML 几百 KB 级，NeDB 单文档无压力；图片一律外链（图片库 URL）不入库 |
| 已知坑 | 不用带 `.` 的字段键（Poster markCounts 2026-11-18 事故教训） |

访问链路照抄 fsAnnotations/fsFavorites 模式：main 进程 service 直用 `services.repository`，新增 IPC `content:list/get/save/remove`（handleOk 包装、toPlain 脱壳，IPC 门禁合规），preload + env.d.ts 同步。

## 三、UI 设计

- `tool.manifest.json` menus 增加 `{ id: 'contents', label: '内容管理' }`（files 与 profiles 之间）；`UploadManagerPage.vue` pages 注册 `ContentsPage`（badge-studio 多菜单范式：入口壳 + pages/ 子目录）。
- **列表页**：el-table（名称 / 字数 / 更新时间 / 标签 / 操作列），操作按钮语义配色（primary=编辑、success=分享、danger=删除，text 变体）；顶部「新建内容」primary 按钮。
- **编辑页**：内容动辄千字，**建议整页视图切换（列表 ⇄ 编辑）而非弹框**——与 rich-text 全屏适配天然契合（待拍板 §六-3）。表单：名称 el-form `label-width="auto"` 必填校验 + `RichTextEditor`（wangEditor 封装，字数统计内置）。
- 图片上传与图片库：`onUploadImage` + `image-library` 桥接注入，照 edm-studio `SampleForm.vue` 的接入形态（C2 唯一注入点）；注入实现放 `tools/upload-manager/src/renderer/image-library.ts`。文章里的图片 URL 是图片库外链（云/远端域名或分享链接），不落本地。

## 四、文章分享方案对比（核心讨论点）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 快照导出 + 现有文件分享**（建议一期） | 保存/分享时把文章渲染成独立 HTML（`toDisplayHtml` + 阅读页模板壳，内联基础排版 CSS）写入应用数据目录 `contents-exports/<id>.html`，走现有 ShareHub `createTicket(root=该文件)` | **零内核改动**：口令 ak、二维码、TTL/永久、撤销/续期、访问日志、`?ak=` 规则全部白拿；快照语义=「发布」，文章改动不影响已发链接（可「更新快照」重导出） | 非活分享：文章更新后需手动更新快照 |
| B. 内容活路由 | share-core 内核加 route kind=`content`（hub-state 存 contentId），handler 直接从 NeDB 读 html 出页 | 分享永远最新，无导出文件 | 动分享内核 + 持久化状态扩展；文章删除/改名后链接悬空；kernel 改动要过 09 全套验收 |
| C. 目录级分享 | root=exports 目录 + 目录列表页（海报列表前缀模式） | 一条链接浏览多篇文章 | 暴露全部文章名，隐私面大，不推荐默认 |

**图片可达性说明（A/B 通用）**：文章内图片是图片库外链——云/远端域名直链访问者可直接加载；若图片走本地 ShareHub 分享链接，则要求访问者在同一局域网且对应路由有效（分享页加提示文案）。

**建议**：一期落 A；B 列二期（真出现「改完即生效」诉求再做，届时内核 handler 按 kind 分发即可平滑升级）。
