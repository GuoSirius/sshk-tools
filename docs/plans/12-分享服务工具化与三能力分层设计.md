## 一、现状盘点：三大基础能力的分层现状

| 能力 | 能力实现层 | 配置数据 | 配置 UI | 工作台 UI | 消费方 |
|---|---|---|---|---|---|
| **模型** | 应用层：主进程网关 | `app.llm.*`（唯一权威） | 工具层 model-console | 工具层（对话调试） | 全部工具经 host capabilities 共用 |
| **上传/文件管理** | 应用层：`upload-core` + `upload:*` | 通道 profile 已应用级 `app.upload`（R26）；**密钥本轮提升** `app:tool:file-manager:*` → `app:upload:*`（#6 拍板） | 工具层（通道配置页） | 工具层（文件系统页） | file-manager 自用；edm-studio / template-tool / 设置预设导出经 `api.upload.*` |
| **分享** | 应用层：`@sshk/share-core`（ShareHub 单例）+ `shareHub:*` | `app.shareHub.*` + hub-state.json + **访问日志（本轮持久化，见 §七）** | 应用设置 ShareTab（6 卡片 530 行，过载）→ 拆工具 | 无 → share-manager 工具 | 各工具 ShareDialog（toolId 归属）；挂载/代理为纯服务能力 |

**关键事实**：
- 分享的能力与数据已在应用层；拆分主体是 UI 层工程。
- 但本轮**访问日志持久化 + 导出是内核增强**（原档"数据零迁移"定性对 UI 成立、对日志不成立），见 §七。
- 三能力目标层见 §九统一总表。

## 二、分层判据（本档定版，后续新能力按此归位）

1. **消费面**：被 ≥2 个工具消费的能力/配置 → 应用层；单工具专属 → 工具层（YAGNI）。
2. **密钥与安全**：密钥一律应用层（safeStorage/主进程注入），工具层零接触。
3. **唯一权威**：跨工具必须一致的数据 → 应用层单一数据源；UI 只是视图，允许多处入口。
4. **UI 性质**：配置型/管理台型 UI → 工具层；应用级少量开关（自启、端口、允许索引）→ 应用设置。
5. **可禁用性**：拆到工具的 UI 必须保证「工具未安装时应用层入口仍可用」。

## 四、分享管理工具化方案

### 4.1 新工具 `share-manager`（#2 拍板：name「分享管理」）
| 项 | 内容 |
|---|---|
| manifest | id `share-manager`，name **「分享管理」**，icon auto，`entryRoute: 'routes'` |
| 菜单（2 个） | `routes` 路由管理（默认）/ `logs` 访问日志 |
| 工具配置（`configLayout: multi`，3 页） | `service` 服务配置（服务状态 + 基础设置）/ `mounts` 挂载管理 / `proxies` 代理管理 |
| 渲染结构 | 顶层唯一 `ShareManagerPage.vue` 壳按 menu prop 分发；菜单页 `pages/RoutesPage.vue`、`pages/LogsPage.vue`；配置页按既有机制注入（3 配置组件） |
| 代码来源 | 从 `ShareTab.vue` 抽卡片迁移（挂载/代理/路由/日志四段近乎原样搬），`service` 页 = 状态卡片 + 基础设置卡片 |

### 4.2 应用设置 ShareTab 瘦身
- **保留**：服务状态卡片、**基础设置卡片（#4 拍板：字段全保留 = 端口 / 网卡地址 / 自启 / 允许目录索引 / 分享时长）**。
- **移除**：挂载目录、代理规则、路由管理、访问日志四段 → 迁入工具。
- 两处入口（应用设置 vs 工具，#5 拍板）：**同键读写 `app.shareHub.*` + 同 IPC `shareHub:*`，天然一致、无需同步机制**；工具未安装时应用设置两卡片完整可用。

### 4.3 数据与 IPC
- 配置键、hub-state.json、share-core 内核、`shareHub:*` 通道主体不动。
- 路由特权（#3）：`list` 不传 toolId 即全量、`revoke/renew` 不传或传 `*` 即放行——**现有 handler 已支持，零内核改动**（详见 §六①）。是否加硬鉴权待定（§六①）。
- 访问日志持久化 + 导出：唯一需要动内核的部分（§七）。

### 4.4 不做清单（边界）
- 不动 file-manager 内 ShareDialog。
- 不动挂载/代理的保存即生效机制。
- 应用设置不新增任何分享入口跳转。
- ~~不做访问日志持久化~~ → **删除本条**（#1 推翻）。

## 六、新发现（需要你决定，均已落档）

> 你在需求里授权「中途发现新问题/新想法都可落档」。以下 4 项是我走读代码后的真实发现，按优先级排列。

### ① 路由特权：现有 IPC 已是「自报身份」软约束，零改动即可拿到特权——但要不要加硬校验？
走读 `apps/desktop/src/main/share-hub.ts:203-219`：`list(toolId?)` 传了才过滤、不传返回全量；`revoke/renew(id,…,toolId?)` 仅当 caller 存在且非 `*` 时校验归属，否则放行。
- **结论**：plans/12 原稿说的「list 支持全量 + revoke/renew 加白名单」两处内核改动**其实都不用做**——share-manager 不传 toolId 即得全量管理权。
- **风险**：这是软约束——任何渲染进程（含外部工具包）都能不传 toolId 绕过归属校验。现状 file-manager ShareDialog 是"自觉传自己 toolId"。
- **建议**：本轮**保持软约束**（零改动、与现状一致），仅 share-manager 调用约定不传 toolId；硬校验（按 webContents 绑定可信 toolId）另立安全加固项，不混进本轮。**待你拍板**。

### ② 访问日志持久化落点：NeDB 集合 vs 内核独立 jsonl
- 方案甲 **NeDB 新集合 `shareLogs`**（加入 BACKUP_COLLECTIONS）：与现有数据层一致、可被导出 zip 带走、查询/过滤/分页方便；但每次访问都写库有 I/O，需节流批量写。
- 方案乙 **内核独立 `share-logs.jsonl`**（applicationData 下，与 hub-state.json 并列）：append-only 最轻、不污染备份集合、内核自持；但查询/分页要在内核实现、不随备份 zip（除非单独纳入）。
- **建议**：方案甲（NeDB 集合），理由：日志属用户数据、备份同行、UI 过滤分页现成；写入用 500ms 防抖批量 flush（复用 share-core 现有 persistTimer 模式）。**待你拍板**。

### ③ 日志容量上限与清理策略
持久化后不再是 500 条环形。建议保留「最近 N 条 + 按天滚动」，默认 N=5000、保留 30 天，超限删最旧；提供「清空日志」按钮（danger，二次确认）。**待你拍板**容量值。

### ④ 日志导出范围与字段
CSV 字段建议：`时间(北京) / 来源IP / 路径 / 状态码 / 命中路由ID / 归属工具 / 标签`（后两列由 routeId 反查 hub 路由表，路由已撤销则留空）。导出范围建议**当前筛选结果**（配合 §八-3 的过滤条件），另给「导出全部」。**待你拍板**。

## 七、访问日志持久化与导出（#1/#7，实现设计）

- 数据结构：`ShareAccessLog` 现为 `{ at, ip, path, status, routeId }`（5 字段）。持久化沿用该结构，不扩字段（归属工具/标签由 routeId 反查，避免日志冗余存储路由快照）。
- 写入链路：share-core `handle()` 命中路由时 `this.logs.push(...)` → 本轮增「同时写入持久化层」（方案甲=NeDB service 注入回调，方案乙=jsonl append），500ms 防抖批量。
- 读取链路：新增 `shareHub:logs(query)` 通道（分页/时间范围/IP/状态码/路由过滤）替代 status() 里塞 500 条；`status()` 仍保留最近 500 条供设置页两卡片无需日志的场景（或彻底移除 logs 字段，待 §八 实现时定）。
- 导出：`shareHub:exportLogs(query)` → 主进程生成 CSV 文本 → 渲染层 `os:pickSave` 落盘（复用 backup 的保存对话框能力）。
- 备份：若采方案甲，shareLogs 进 BACKUP_COLLECTIONS 随 zip 导出/导入（与 contents 一致）。

### 8.1 路由管理页 `RoutesPage`（默认入口，新工具主界面）

- **表格列**：序号(fixed left) / 工具 / 标签 / 访问数 / 剩余时间(永久=warning tag) / 创建时间 / 状态(tag：有效success/过期danger/永久warning) / 允许索引(tag) / 操作(fixed right)。
- **列操作**：续期(primary) / 撤销(danger，二次确认) / 复制链接(success) / 更多▾（改 TTL、永久有效、切换允许索引）。
- 可见**全量路由**（含 file-manager 等所有工具创建），工具列可过滤。

### 8.2 访问日志页 `LogsPage`（新菜单）
- **顶部**：搜索框（IP/路径模糊）；过滤（时间范围：近1h/24h/7天/全部；状态码：全部/2xx/3xx/4xx/5xx；工具/路由下拉）；「导出 CSV」(success)、「清空日志」(danger，二次确认)、「刷新」；分页（若采持久化）。
- **表格列**：序号(fixed left) / 时间(北京) / 来源IP / 路径 / 状态码(2xx绿/4xx5xx红) / 命中路由(routeId→标签，撤销后显示「已撤销」) / 归属工具(反查) 。
- **列操作**：一般只读；必要时「按此IP过滤」「按此路由过滤」(text 按钮)。

### 8.3 服务配置页 `ServicePage`（工具配置，与应用设置两卡片等价）
- **服务状态卡片**：运行中/端口/展示IP + 启动(success)/重启(primary)/停止(warning)/停止并清空(danger，二次确认)。
