## 一、现状盘点：三大基础能力的分层现状

| 能力 | 能力实现层 | 配置数据 | 配置 UI | 工作台 UI | 消费方 |
|---|---|---|---|---|---|
| **模型** | 应用层：主进程网关 | `app.llm.*`（唯一权威） | 工具层 model-console | 工具层（对话调试） | 全部工具经 host capabilities 共用 |
| **上传/文件管理** | 应用层：`upload-core` + `upload:*` | 通道 profile 已应用级 `app.upload`（R26）；密钥已提升 `app:upload:<pid>`（ccc2efe 已落地） | 工具层（通道配置页） | 工具层（文件系统页） | file-manager 自用；edm-studio / template-tool / 设置预设导出经 `api.upload.*` |
| **分享** | 应用层：`@sshk/share-core`（ShareHub 单例）+ `shareHub:*` | `app.shareHub.*` + hub-state.json + **访问日志（本轮持久化到 NeDB，见 §七）** | 应用设置 ShareTab（6 卡片 530 行，过载）→ 拆工具 | 无 → share-manager 工具 | 各工具 ShareDialog（toolId 归属）；挂载/代理为纯服务能力 |

**关键事实**：
- 分享的能力与数据已在应用层；拆分主体是 UI 层工程。
- 访问日志持久化 + 导出 + 读取链路改造是**内核改动**（原档"数据零迁移"定性对 UI 成立、对日志不成立）。
- 三能力目标层见 §九统一总表。

## 二、分层判据（本档定版，后续新能力按此归位）

1. **消费面**：被 ≥2 个工具消费的能力/配置 → 应用层；单工具专属 → 工具层（YAGNI）。
2. **密钥与安全**：密钥一律应用层（safeStorage/主进程注入），工具层零接触。
3. **唯一权威**：跨工具必须一致的数据 → 应用层单一数据源；UI 只是视图，允许多处入口。
4. **UI 性质**：配置型/管理台型 UI → 工具层；应用级少量开关（自启、端口、允许索引）→ 应用设置。
5. **可禁用性**：拆到工具的 UI 必须保证「工具未安装时应用层入口仍可用」。

## 三、分层分析结论

### 3.1 不动（维持）
模型整体分层（标杆）；上传能力 upload-core / `upload:*`；分享内核与 IPC 主体（share-core / `shareHub:*`）——除 §七的日志链路外。

### 3.2 需改进（本轮处置）
| 项 | 处置 |
|---|---|
| 分享管理 UI 全在应用设置 | 拆出新工具 **「分享管理」`share-manager`**（§四），应用设置瘦身为两卡片 |
| 上传通道**密钥命名空间**错位 | 提升 `app:tool:file-manager:<pid>` → `app:upload:<pid>`（ccc2efe 已落地，本档确认纳入 plans/12 范围） |
| 分享路由跨工具特权 | 可管任意工具路由；IPC 本就自报身份，零内核改动。**硬校验另立安全加固项**（§六①） |
| 访问日志链路 | 持久化 + 独立查询 + 导出 + 删除，读取链路彻底改造（§七） |
| 路由「更新时间」 | 新增 `updatedAt` 字段，**不回落、不兼容旧文件**（§十一① / §三.4） |

### 3.3 访问日志：由「观察候选」改为「本轮全量做」
原档把「访问日志持久化」列为观察候选、「CSV 导出」建议二期——**均作废**。本轮做：持久化（NeDB）、独立查询通道、CSV 导出、单条删除、批量删除、容量可配、时间范围自选+快捷。

### 3.4 破坏性改动清单（依总原则，全部接受、不做兼容层）
| 改动 | 影响 | 处置 |
|---|---|---|
| 路由加 `updatedAt`（必填） | 旧 hub-state.json 路由无此字段 | **不迁移、不回落**；旧状态文件按新结构读，缺字段视为脏数据丢弃（旧链接失效，用户接受） |
| `HubStatus` 删 `logs` 字段 | 任何 `status().logs` 消费方 | **全量删除消费点**，不留兜底字段（§十二②走查清单） |
| 内存环形日志缓冲取消 | 升级瞬间内存日志丢失 | 接受，不做"旧内存日志补写 NeDB" |
| 日志改稳定键 `id` | NeDB 旧集合（若有）无 id | 不兼容旧集合；shareLogs 集合本轮新建，无历史数据 |
| ShareTab 日志卡片删除 | 设置页少一卡片 | 直接删，不做跳转/占位 |
| 分享链接 token / 分享行为 | 路由结构变化 | 旧链接可能失效，按总原则接受；发布说明注明「升级后请重新生成分享链接」 |

## 四、分享管理工具化方案

### 4.1 新工具 `share-manager`（name「分享管理」）
| 项 | 内容 |
|---|---|
| manifest | id `share-manager`，name **「分享管理」**，icon auto，`entryRoute: 'routes'` |
| 菜单（2 个） | `routes` 路由管理（默认）/ `logs` 访问日志 |
| 工具配置（`configLayout: multi`，3 页） | `service` 服务配置（服务状态 + 基础设置 + **日志容量设置**）/ `mounts` 挂载管理 / `proxies` 代理管理 |
| 渲染结构 | 顶层唯一 `ShareManagerPage.vue` 壳按 menu prop 分发；菜单页 `pages/RoutesPage.vue`、`pages/LogsPage.vue`；配置页按既有机制注入（3 配置组件） |
| 代码来源 | 从 `ShareTab.vue` 抽卡片迁移（挂载/代理/路由/日志四段）；`service` 页 = 状态卡片 + 基础设置卡片 + 日志容量卡片 |

### 4.2 应用设置 ShareTab 瘦身
- **保留**：服务状态卡片、**基础设置卡片（字段全保留 = 端口 / 网卡地址 / 自启 / 允许目录索引 / 分享时长）**。
- **移除**：挂载目录、代理规则、路由管理、**访问日志四段** → 迁入工具。日志卡片随读取链路改造一并从 ShareTab 删除。
- 两处入口（应用设置 vs 工具）：**同键读写 `app.shareHub.*` + 同 IPC `shareHub:*`，天然一致、无需同步机制**；工具未安装时应用设置两卡片完整可用。

### 4.3 数据与 IPC
- 配置键、hub-state.json、share-core 内核主体、`shareHub:*` 既有通道不动；新增 `shareHub:logs` / `shareHub:exportLogs` / `shareHub:deleteLogs` 三条通道（§七）。
- 路由特权：不传 toolId 即全量/revoke·renew 放行，现有 handler 已支持、零内核改动。**硬校验按 webContents 绑定可信 toolId 另立安全加固项，本轮不做**（§六①）。
- 访问日志持久化 + 导出 + 删除：唯一需要动内核的部分（§七）。

### 4.4 不做清单（边界）
- 不动 file-manager 内 ShareDialog。
- 不动挂载/代理的保存即生效机制。
- 应用设置不新增任何分享入口跳转。
- **本轮不做**路由 IPC 硬鉴权（另立安全项）。

## 六、新发现 4 项：定案（19:54）

### ① 路由特权硬校验 → **另立安全加固项，本轮零改动**
现状 `share-hub.ts:203-219` 为「自报身份」软约束；share-manager 不传 toolId 即得全量管理权。本轮保持软约束，**按 webContents 绑定可信 toolId 的硬校验另立安全加固项**。

### ② 访问日志持久化落点 → **NeDB 新集合 `shareLogs`**
加入 BACKUP_COLLECTIONS，随备份 zip 导出/导入；写入 500ms 防抖批量 flush。

### ③ 日志容量上限与清理策略 → **默认 N=5000 / 保留 30 天，且可设置**
滚动清理：超限删最旧 + 按天滚动删 30 天前记录，在 flush 时批量做。配置键与入口见 §十一③（本轮确认）。

### ④ 日志导出范围与字段 → **全部采纳**
CSV 字段：`时间(北京) / 来源IP / 路径 / 状态码 / 命中路由ID / 归属工具 / 标签`（后两列由 routeId 反查，已撤销留空）；范围：当前筛选结果 + 导出全部两档。导出随筛选联动（§十一⑤）。

## 七、访问日志持久化、读取链路改造与删除

- **数据结构**：`ShareAccessLog` 现 `{ at, ip, path, status, routeId }`。本轮加**稳定键 `id`**（UUID，写入时生成，不依赖 NeDB 回执，见 §十一②）；归属工具/标签由 routeId 反查，不冗余存路由快照。
- **写入链路**：share-core `log()` 命中时入队（带 UUID id）→ 500ms 防抖批量写入 NeDB `shareLogs`；清理（N/30 天）在 flush 时一并做。删除未落库记录时直接从内存队列按 id 移除。
- **读取链路（彻底改造，总原则）**：
  - `HubStatus` **移除 `logs` 字段**；`ShareHub.status()` 不再返回日志；内存环形缓冲 `this.logs` 取消（仅保留 flush 前暂存队列，不再是读取源）。
  - 新增 `shareHub:logs(query)`：NeDB 分页查询，支持时间范围（EP daterange 自选起止 + 快捷）、IP/路径模糊、状态码、工具/路由过滤。
  - 设置页 ShareTab 访问日志卡片**删除**（唯一消费方，§4.2）。
  - **不留双轨**：不做"status 保留最近 N 条"，重启后历史只从 NeDB 读。
- **导出**：`shareHub:exportLogs(query)` → 主进程生成 CSV（**UTF-8 BOM 开头，防 Excel 中文乱码**，见 §十二①）→ 渲染层 `os:pickSave` 落盘。
- **删除**：`shareHub:deleteLogs(ids)` 单条/批量；「清空」独立 action；均 danger 二次确认（禁遮罩禁 ESC）。边界见 §十一⑥。
- **备份**：`shareLogs` 进 BACKUP_COLLECTIONS 随 zip 导出/导入（与 contents 一致）。

## 八、界面规划（本轮定版）

> 沿用铁律：表格控件紧凑（22px/tag18px/11px）、label-width=auto、危险操作二次确认、语义配色（primary 查看/新建、success 上传下载、warning 复制导出、danger 删除）、常用操作外置+次要进更多▾。

### 8.1 路由管理页 `RoutesPage`（默认入口）
- **顶部**：搜索（标签/工具/路径模糊）；过滤（工具：全部/各 toolId；状态：全部/有效/已过期/永久）；右侧「刷新」(success)；路由数统计 tag。批量操作不适用。
- **表格列**：序号(fixed left) / 工具 / 标签 / 访问数 / **更新时间** / 剩余时间(永久=warning tag) / 创建时间 / 状态(tag：有效success/过期danger/永久warning) / 允许索引(tag) / 操作(fixed right)。
- **列操作**：续期(primary) / 撤销(danger，二次确认) / 复制链接(success) / 更多▾（改 TTL、永久有效、切换允许索引）。
- 可见**全量路由**，工具列可过滤。「更新时间」= `updatedAt`，create 与 renew（含「重新生成」= 撤销旧+建新）均刷新；访问命中 `hits` 不刷新。

### 8.2 访问日志页 `LogsPage`（本轮大改）
- **顶部**：搜索（IP/路径模糊）；**时间范围 = EP `el-date-picker type="daterange"`**：`:shortcuts` 快捷（近1h / 近24h / 近7天 / 全部）+ 自选起止，`value-format="YYYY-MM-DD"`，`v-model` 为长度 2 数组，`start-placeholder`/`end-placeholder`，`unlink-panels`（左右面板独立）；快捷 `shortcuts` 项形如 `{ text: '近 7 天', value: [Date, Date] }`（函数形式亦可，用当天 00:00:00 到 now）。EP 版本 2.14.8。时间语义与查询统一见 §十二③。
- 过滤：状态码（全部/2xx/3xx/4xx/5xx）、工具/路由下拉；右侧「导出 CSV」(success)、「批量删除」(danger，二次确认)、「清空日志」(danger，二次确认)、「刷新」；分页。
- **表格列**：勾选框(fixed left，供批量删除) / 序号 / 时间(北京) / 来源IP / 路径 / 状态码(2xx绿/4xx5xx红) / 命中路由(routeId→标签，撤销后显示「已撤销」) / 归属工具(反查) / 操作(fixed right)。
- **列操作**：「按此IP过滤」「按此路由过滤」(text 按钮) + **「删除」(danger，二次确认)**。

### 8.3 服务配置页 `ServicePage`（工具配置）
- **服务状态卡片**：运行中/端口/展示IP + 启动(success)/重启(primary)/停止(warning)/停止并清空(danger，二次确认)。
- **基础设置卡片（全保留）**：随应用启动开关、监听端口、分享地址IP（下拉+手输）、默认分享时长、允许访问目录开关——一行一控件、label-width=auto、长说明进❓detail。
- **日志容量卡片**：最多保留条数（默认 5000）、保留天数（默认 30）、「清空日志」(danger，二次确认)——数字输入 + 保存，即时生效跨重启；边界校验见 §十二④。

### 8.4 挂载管理页 `MountsPage`（工具配置）
- 顶部：搜索（目录/别名/地址）；「添加挂载」(success)；保存按钮(primary)。
- 卡片行：目录 / 挂载点别名 / 访问密钥(show-password) / 允许索引开关 / 启用开关 / 地址+复制 / 删除(danger，二次确认)。逐项保存即生效。

### 8.5 代理管理页 `ProxiesPage`（工具配置）
- 顶部：搜索（前缀/目标地址）；「添加规则」(success)；保存(primary)。
- 卡片行：目标地址 / 保留Host复选 / 前缀 / 启用开关 / 地址+复制 / 删除(danger，二次确认)。前缀必填校验。

### 8.6 应用设置·分享服务 tab（保留两卡片）
- 仅服务状态卡片 + 基础设置卡片，字段与 §8.3 前两卡片完全一致（同键读写）。**日志卡片已删除**（§4.2/§七）。

## 十一、优化点：本轮定案（原「待拍板」已全部拍板）

### ① 路由「更新时间」数据源 → **新增 `updatedAt`，不回落旧数据**
- `ShareRoute` / `ShareRouteInfo` 加 `updatedAt: number`；create 时 = createdAt，renew/patch（续期、改 TTL、永久有效、切换允许索引、改口令）与「重新生成」刷新；`hits` 访问不刷新。
- **按总原则**：不加 `?? createdAt` 兼容回落，旧 hub-state.json 缺字段的路由按脏数据丢弃（旧链接失效，已接受）。

### ② 访问日志删除稳定键 → **写入时自生成 UUID（id 字段）**
- `ShareAccessLog` 加 `id: string`，share-core `log()` 入队时即 `randomUUID()`，不依赖 NeDB `_id` 回执；查询通道返回带 id 的行；删除按 id 批量。
- 未落库的队列记录按 id 直接从内存队列移除（无需等 NeDB 回执）。

### ③ 日志容量配置键与入口 → **确认**
- `app.shareHub.logMaxCount`（默认 5000）、`app.shareHub.logRetentionDays`（默认 30）；**只放工具 service 页「日志容量」卡片**，应用设置两卡片不重复此配置；配置变更即时生效、跨重启保留。

### ④ `status()` 移除 logs 后的兼容性走查 → **彻底检查、清理**
- 逐项清理（详见 §十二②清单）：`HubStatus.logs` 类型、`ShareHub.status()`、`ShareTab` 日志卡片、env.d.ts / preload / types.ts 的 logs 字段、任何 `status().logs` 引用、verify-steps 相关断言。全仓 grep 零残留才算完成。

### ⑤ 导出与筛选联动 → **采纳**
- 「导出当前筛选结果」带上日志页全部过滤条件（时间范围/工具/状态/搜索），文件名带时间范围戳（`share-logs-20261119-1954.csv`），避免导出与屏幕所见不一致。

### ⑥ 清空 vs 批量删除 vs 滚动清理三者边界 → **按拆分实现**
- 清空=全删（二次确认）；批量删除=按选中 id（二次确认）；滚动清理=N/30 天自动（无提示）。三者不互相覆盖，清空后新访问继续按容量策略累积。

## 十二、本轮新问题/优化点（我发现的，需你拍板）

> 你授权「继续提新问题和新需求」。以下 5 项是映射到代码时新发现的，均给建议默认。

### ① 导出 CSV 的 Excel 中文乱码
- 字段含中文（时间标签/归属工具/标签），直接输出 UTF-8 在 Windows Excel 打开会乱码。
- **建议**：CSV 文本以 UTF-8 BOM（`\ufeff`）开头。零成本、不影响其它解析器。**按此默认推进，无需拍板**（除非你要纯 UTF-8）。

### ② `status()` 移除 logs 的彻底走查清单（§十一④展开）
- 需清理的具体位置（基于走读）：`packages/shared/src/types.ts` 的 `HubStatus.logs` 与 `ShareAccessLog` 注释「环形缓冲最近 500 条」、`packages/share-core/src/index.ts` 的 `status()`、`apps/desktop/src/renderer/components/settings/ShareTab.vue` 日志卡片、`env.d.ts` / `preload` 的 `HubStatus` 返回类型、任何测试断言。**按此清单逐项 grep 清零，无需拍板**。

### ③ daterange 自选与快捷的时间语义统一
- EP daterange 默认按自然日（00:00:00 起），快捷「近1h/近24h」是滚动窗口到当前时刻——两者时间粒度不同，混用会让查询边界不一致。
- **建议**：查询通道统一收 `from`/`to` 毫秒时间戳；快捷项 value 用 `[now - N, now]`（精确到毫秒），自选 daterange 取 `[当天00:00, 次日00:00-1ms]`（自然日闭区间）。UI 层组装好再传内核，内核不关心 EP。**按此默认推进**。

### ④ 日志容量设置的边界值
- 可设置后，用户输入 0 / 负数 / 超大值需要约束。
- **建议**：`logMaxCount` clamp 到 1~100000（默认 5000），`logRetentionDays` clamp 到 1~365（默认 30）；0 或非法值回弹到默认并 toast 提示。前端数字框 min/max + 主进程再校验一道。**按此默认推进**。

### ⑤ 「清空」文案歧义（service 页「停止并清空」vs 日志页「清空日志」）
- service 页的「停止并清空」清的是**路由 + 状态文件**（`hub.clear()`），日志页的「清空日志」只清 `shareLogs` 集合——两者都叫「清空」易误点。
- **建议**：文案区分——service 页改「停止服务并清空全部路由」（tooltip 注明「不影响访问日志」），日志页改「仅清空访问日志」（tooltip 注明「不影响分享链接」）。**按此默认推进**。

> ⑤ 中若你希望「停止并清空」连日志一起清（即清空 = 路由 + 日志全清），告诉我改为联动；当前按两者独立设计。
